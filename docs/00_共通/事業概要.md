# premake 事業概要

> 作成日: 2026-07-17 / 根拠: [10_v2_仕様/00_要件定義](../10_v2_仕様/00_要件定義.md)

premake は、クリニックの自由診療予約を規制対応込みで一気通貫管理する院内 SaaS である。第一弾は実在クリニック 1 院への導入から始めるが、テナント・メニュー・予約・患者を基盤とする「器」は業種非依存に設計し、2 院目・別用途をデータ追加のみで載せられることを目指す。

医療提供主体はあくまでクリニックであり、premake はソフトウェアベンダーに徹する。マッチング・決済代理受領・施術者斡旋は行わず、患者には「クリニック X の予約ページ」として見える(premake ブランドは前面に出さない)。決済機能は持たず、料金はメニュー属性として表示フラグ付きで保持する。

予約は 3 層で捉える。(1) スタッフ(業務委託看護師を含む)が部屋×時間の施術枠を確保し、(2) 患者の予約(公開ページ経由または受付の代理入力)が枠に入り、(3) 院内の予約台帳で全体を管理する。アートメイクのようにカウンセリング→施術→リタッチと続くセッション型メニューにも対応する。

主な機能は、スタッフ認証・テナント設定・監査ログ、メニュー/部屋/担当/施術枠の管理、予約台帳カレンダーとダブルブッキング防止、患者マスタ・名寄せ・問診、患者向け公開予約(テナント設定でオン/オフ可、メール確認リンクで確定)、メール通知・リマインダー、運営(ops)向けテナント管理・利用計測ダッシュボード。公開ページは症例写真・体験談なしの最小構成とし、医療広告リスクを抑える。

事業目的は、(1) 実クリニックの予約運用を置き換えて「予約管理」が実ペインであることを検証すること、(2) 信頼関係を深めながらメーカー試験・クロスセル等の拡張需要のシグナルを収集すること、(3) 業種非依存の基盤をコードとして建造すること。看護師マッチング・スペース掲載・決済・レビュー・チャット等は行わない。Phase 2 候補として指示書/施術記録の電子化、Stripe 決済、LINE 連携、シフト管理等を導入後の要望に応じて検討する。
