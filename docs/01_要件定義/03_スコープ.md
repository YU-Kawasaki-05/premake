## 4. 機能間の主要依存関係

```mermaid
graph LR
    A[認証 A] --> B[施設・スペース B]
    A --> C[予約 C]
    B --> C
    C --> D[指示書・施術記録 D]
    C --> E[決済 E]
    D --> E
    A --> K[顧客予約 K]
    K --> C
    K --> E
    H[運営管理 H] -.監査.-> A
    H -.監査.-> C
    H -.監査.-> D
    H -.監査.-> E
    F[メッセージ F] -.通知.-> C
    F -.通知.-> D
    F -.通知.-> E
    F -.通知.-> K
    Cross[横断: 監査ログ / ジョブ基盤 / PII マスキング] -.基盤.-> A
    Cross -.基盤.-> C
    Cross -.基盤.-> D
    Cross -.基盤.-> E
    J[ダッシュボード J] -.集計.-> C
    J -.集計.-> E
    G[レビュー G] -.イベント.-> C
    Org[法人レベル<br/>FR-82〜85] --> B
```

> **コアクリティカルパス**: A → B → C → D → E → K（β β βこの 6 つが揃って初めて 1 件の施術が完結する）
> **横断要件**: 監査ログ・PII マスキング・キュー基盤は全機能の前提
