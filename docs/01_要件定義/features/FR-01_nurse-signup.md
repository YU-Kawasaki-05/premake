# FR-01: 看護師サインアップ

## 概要
看護師（U-01）が premake にメールアドレス + パスワードでアカウント登録する。サインアップ後、メール確認 (FR-06) と看護師免許審査 (FR-08) を経て初めて予約機能が解放される。Google OAuth 経由は FR-81 で別途扱う。

## アクター
- U-01 施術看護師（未登録）

## 入力データ
| フィールド | 型 | 必須 | 制約 | 例 |
|-----------|---|------|------|---|
| email | string | ○ | RFC5322 形式、重複不可、255 文字以内 | nurse@example.com |
| password | string | ○ | 12 文字以上、英大小文字＋数字＋記号を各 1 文字以上 | `Aa1!securepass` |
| 氏名（漢字） | string | ○ | 1〜50 文字 | 山田 花子 |
| 氏名（カナ） | string | ○ | 全角カナ、1〜50 文字 | ヤマダ ハナコ |
| 電話番号 | string | ○ | 日本形式 (E.164 推奨)、SMS 受信可能であること | +81-90-1234-5678 |
| 利用規約・プライバシーポリシー同意 | boolean | ○ | true 必須 | true |

## 出力 / 結果
- **正常系**:
  - `users` テーブルに `role=nurse, status=email_unverified` で 1 レコード作成
  - 確認メールを送信（FR-06）
  - 「メールアドレスに確認メールを送信しました」画面に遷移
- **異常系**: バリデーションエラーメッセージ表示、レコード未作成

## ビジネスルール
- BR-01-01: メールアドレスは `users.email` でユニーク。重複時は登録不可。
- BR-01-02: パスワードは bcrypt cost 12 以上でハッシュ化して保存。平文は一切ログ・DB に残さない。
- BR-01-03: サインアップ直後の `status` は `email_unverified`。`email_verified` に遷移してから FR-08（免許審査）に進める。
- BR-01-04: 同一 IP からの 1 時間あたりの新規サインアップは 5 件まで（abuse 防止）。超過時は 429 応答。
- BR-01-05: 利用規約・プライバシーポリシー同意なしのサインアップは不可（同意ログを残す）。

## エラーケース
| 条件 | 期待挙動 |
|------|----------|
| 重複メールアドレス | 「このメールアドレスは既に登録されています」/ アカウント未作成 / メール送信なし |
| パスワード強度不足 | 強度不足の理由を明示（「12 文字以上」「記号を含む」など） |
| 不正メール形式 | 「メールアドレスの形式が正しくありません」 |
| 規約未同意 | 「利用規約とプライバシーポリシーへの同意が必要です」 |
| レート制限超過 | 「しばらく時間をおいてからお試しください」 / 429 |

## 受入基準（AC）

### AC-01-01: 正常系 — 新規看護師サインアップ
```gherkin
Given メール "nurse@example.com" は未登録
When 有効な必須項目（メール / パスワード "Aa1!securepass" / 氏名 / カナ / 電話番号 / 規約同意）を入力
And 「登録」をクリック
Then users テーブルに role=nurse, status=email_unverified のレコードが作成される
And 確認メールが nurse@example.com に送信される
And 「確認メールを送信しました」画面が表示される
```

### AC-01-02: 異常系 — 重複メール
```gherkin
Given メール "x@example.com" は登録済み
When "x@example.com" でサインアップを試みる
Then エラー「このメールアドレスは既に登録されています」が表示される
And users テーブルに新規レコードは作成されない
And 既存ユーザーへのメール送信も発生しない（情報漏洩防止）
```

### AC-01-03: バリデーション — パスワード強度
```gherkin
When パスワードに "{password}" を入力
Then バリデーション結果が "{result}"

Examples:
  | password | result |
  | abc | エラー: 12 文字以上 |
  | abcdefghijkl | エラー: 大文字・数字・記号を含む |
  | Abcdefghijkl | エラー: 数字・記号を含む |
  | Abcdefghijk1 | エラー: 記号を含む |
  | Aa1!securepass | OK |
```

### AC-01-04: レート制限
```gherkin
Given 同一 IP から 1 時間以内に 5 件のサインアップが完了している
When 6 件目のサインアップを試みる
Then HTTP 429 が返る
And メール送信は発生しない
```

### AC-01-05: パスワードハッシュ化
```gherkin
Given サインアップが完了した
When DB の users テーブルを直接参照する
Then password 列はハッシュ化されており、平文文字列は保存されていない
And ハッシュは bcrypt cost 12 以上で生成されている
```
