# FR-02: 施設管理者招待型サインアップ（4経路）

## 概要
施設管理者（U-02）は自由サインアップではなく、4 つの招待経路のいずれかでアカウントを作成する（DEC-18）。
1. **招待リンク（メール）**: U-04 運営 or U-06 法人管理者がメールで送信
2. **招待コード**: U-04/U-06 が発行した 8 桁コードを入力
3. **申請型**: 公開フォームから申請 → U-04 が承認 → 招待リンクが届く
4. **運営代理オンボーディング**: U-04 が事前に施設・管理者情報を入力済み。U-02 はログインだけで利用開始（FR-87）

## アクター
- U-02 施設管理者（未登録）
- 招待発行側: U-04 運営 / U-06 法人管理者

## 入力データ

### 招待リンク経由
| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| invitation_token | string | ○ | URL クエリ。72 時間で失効、1 回限り |
| email | string | ○ | 招待時に指定されたメールと一致必須 |
| password | string | ○ | FR-01 と同じ強度 |
| 氏名 / カナ / 電話番号 | string | ○ | FR-01 と同じ |
| 規約同意 | boolean | ○ | true |

### 招待コード経由
| invitation_code | string | ○ | 8 桁英数字、大文字小文字区別なし、72 時間で失効 |
| その他 | - | - | 招待リンク経由と同じ |

### 申請型
| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| 医療機関名 | string | ○ | 1〜200 文字 |
| 開設届出番号 | string | ○ | 自治体発行番号 |
| 担当者氏名 / 役職 / メール / 電話 | string | ○ | - |
| 申請理由 | string | ○ | 50〜1000 文字 |

### 運営代理オンボーディング
- U-02 側の入力は不要。U-04 が代理入力済み（FR-87）
- 初回ログイン時に強制パスワード変更ダイアログ + プロフィール最終確認

## 出力 / 結果
- 招待リンク / コード / 代理: `users` テーブルに `role=facility_admin, status=email_verified` で作成（招待時にメール検証済みのため）。`facility_id` は招待発行時に紐付け済み
- 申請型: `applications` テーブルに `status=pending` で作成 → 運営審査後に招待リンク発行 → 上記フローへ

## ビジネスルール
- BR-02-01: 招待トークン / コードは 72 時間で失効。失効後の利用試行はエラー。
- BR-02-02: 招待トークンは 1 回限り使用。利用済みは即座に失効。
- BR-02-03: 招待発行時に `facility_id` を紐付ける。サインアップ完了で `users.facility_id` が確定。
- BR-02-04: 申請型は U-04 の承認なしに `users` レコードを作成しない。
- BR-02-05: 運営代理オンボーディングの初回ログイン時はパスワード強制変更（DEC-18 / FR-87）。
- BR-02-06: 同一施設に対する施設管理者の人数上限は **5 名まで**（[仮決定]）。

## エラーケース
| 条件 | 期待挙動 |
|------|----------|
| 招待トークン失効 | 「この招待リンクは有効期限切れです」/ 再発行リクエスト導線提示 |
| 招待トークン使用済み | 「この招待リンクは既に使用されています」/ ログイン画面に誘導 |
| 招待時メールと入力メール不一致 | 「招待されたメールアドレスでサインアップしてください」 |
| 申請内容不備 | フィールド単位のバリデーションエラー |
| 申請型の重複申請 | 「同じメールアドレスで申請中です」/ 新規申請を作成しない |

## 受入基準（AC）

### AC-02-01: 正常系 — 招待リンク経由
```gherkin
Given U-04 が email "admin@hospital.jp" 宛に招待リンクを発行（facility_id=F-001 紐付け）
And 招待リンクは 72 時間以内
When admin@hospital.jp の所有者がリンクを開く
And パスワード "Aa1!securepass" + 氏名等を入力
And 「登録」をクリック
Then users テーブルに role=facility_admin, status=email_verified, facility_id=F-001 で作成される
And ダッシュボードに直接遷移する（メール確認スキップ）
And 招待トークンが consumed に更新される
```

### AC-02-02: 招待コード経由
```gherkin
Given U-04 が招待コード "ABC12345" を発行（facility_id=F-001、72 時間有効）
When U-02 候補者がサインアップ画面で招待コード "ABC12345" を入力
And 必須項目を入力
Then users レコードが作成され、ダッシュボードに遷移する
```

### AC-02-03: 申請型 — 申請から承認まで
```gherkin
Given 公開申請フォーム経由で「東京○○クリニック」が申請
When 申請が送信される
Then applications テーブルに status=pending で作成される
And U-04 運営に通知メールが届く
And 申請者に「審査開始」確認メールが届く
When U-04 が申請を承認
Then 招待リンクが申請者メールに送信される
And applications.status=approved に更新される
```

### AC-02-04: 失効した招待リンク
```gherkin
Given 招待リンクが発行されてから 73 時間が経過
When 招待リンクを開く
Then エラー「この招待リンクは有効期限切れです」が表示される
And 「招待元に再発行を依頼してください」のガイダンスが表示される
And users レコードは作成されない
```

### AC-02-05: 招待トークン再利用防止
```gherkin
Given 招待リンクを使ってサインアップが完了している
When 同じ招待リンクで再度サインアップを試みる
Then エラー「この招待リンクは既に使用されています」が表示される
```

### AC-02-06: 運営代理オンボーディングの初回ログイン
```gherkin
Given U-04 が代理オンボーディングで U-02 のレコードを作成（仮パスワード設定済み）
And U-04 が U-02 候補者に初回ログイン情報を共有
When U-02 候補者が仮パスワードでログイン
Then 強制パスワード変更ダイアログが表示される
And プロフィール（氏名・電話番号）の確認画面が表示される
And 変更完了後にダッシュボードに遷移する
```

## サブ機能
- FR-02-1: 招待リンク発行（U-04 / U-06 から）
- FR-02-2: 招待コード発行
- FR-02-3: 申請審査ワークフロー（U-04）
