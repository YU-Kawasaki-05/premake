# FR-05: パスワードリセット

## 概要
ユーザーが自分のメールアドレスでパスワードリセットを要求し、メールで届いたリンクから新パスワードを設定する。

## アクター
- 全認証ユーザー（パスワードを忘れた状態）

## 入力データ

### Step 1: リセット要求
| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| email | string | ○ | RFC5322 |

### Step 2: 新パスワード設定
| reset_token | string | ○ | URL クエリ。30 分で失効、1 回限り |
| new_password | string | ○ | FR-01 と同じ強度 |
| new_password_confirm | string | ○ | new_password と一致 |

## 出力 / 結果
- Step 1: 要求の有無に関わらず「メールを送信しました」表示（メール存在を漏らさない）
- 該当ユーザーが存在すればリセットメール送信
- Step 2 完了で `users.password_hash` 更新、全セッション無効化

## ビジネスルール
- BR-05-01: リセットトークンは 30 分で失効、1 回限り使用。
- BR-05-02: メール存在の有無を漏らさない（タイミング攻撃も含めて応答時間を一定化）。
- BR-05-03: 同一メールへの 1 時間あたりのリセット要求は 5 回まで。
- BR-05-04: パスワード変更後は当該ユーザーの全セッション・全 MFA バックアップコードを無効化（再ログイン要求）。
- BR-05-05: パスワード変更時に通知メールを別途送信（不正検知用）。

## エラーケース
| 条件 | 期待挙動 |
|------|----------|
| 未登録メール | 「メールを送信しました」（実際には送信なし） |
| トークン失効 | 「リンクの有効期限が切れています」/ 再リクエスト導線 |
| トークン使用済み | 同上 |
| 新パスワード強度不足 | FR-01 と同じバリデーション |
| 新パスワード不一致 | 「パスワードが一致しません」 |

## 受入基準（AC）

### AC-05-01: 正常系
```gherkin
Given email "x@example.com" のユーザーが存在
When パスワードリセット要求を送信
Then 「メールを送信しました」と表示される
And reset_token を含むメールが送信される
And users.reset_token, reset_token_expires_at が更新される
When ユーザーがリンクを開き、新パスワード "Aa1!newpass1234" を入力
Then password_hash が更新される
And 全セッションが無効化される
And 「パスワードが変更されました」通知メールが送信される
```

### AC-05-02: メール非存在 — 情報漏洩防止
```gherkin
Given email "unknown@example.com" は未登録
When 当該メールでリセット要求
Then 「メールを送信しました」と表示される（同じ画面遷移・同じ応答時間）
And 実際にはメール送信されない
And メール存在の有無を返却から判別できない
```

### AC-05-03: トークン失効
```gherkin
Given reset_token が発行されてから 31 分経過
When リセットリンクを開く
Then 「リンクの有効期限が切れています」エラー
And 「再度パスワードリセットを要求する」導線が表示される
```

### AC-05-04: トークン再利用
```gherkin
Given reset_token を使ってパスワード変更が完了済み
When 同じリンクを再度開く
Then エラー「このリンクは既に使用されています」
```

### AC-05-05: パスワード変更後のセッション無効化
```gherkin
Given U-01 が複数のデバイスでログイン中
When パスワードリセットを完了
Then 全デバイスの既存セッションが 401 になる
And 新パスワードで再ログインが必要
```

## サブ機能
- FR-05-1: リセットトークン発行
- FR-05-2: パスワード変更・全セッション無効化
- FR-05-3: 変更通知メール
