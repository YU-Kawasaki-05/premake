# FR-06: メールアドレス確認

## 概要
サインアップ時に登録されたメールアドレスの所有確認を行う。確認完了で `users.status=email_verified` に遷移し、後続の審査フェーズ（FR-08, FR-09, FR-10）へ進める。

## アクター
- 全認証ユーザー（FR-01 直後）

## 入力データ
| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| verification_token | string | ○ | URL クエリ。24 時間で失効、1 回限り |

## 出力 / 結果
- 正常系: `users.status` を `email_unverified → email_verified` に更新、ダッシュボードへリダイレクト
- 異常系: 失効・無効トークンエラー

## ビジネスルール
- BR-06-01: トークン有効期限 24 時間、1 回限り。
- BR-06-02: メール再送機能あり。1 時間あたり 3 回まで（429）。
- BR-06-03: 確認完了で監査ログ（FR-76）に `email_verified` を記録。
- BR-06-04: メール送信失敗時は再送 UI を即座に表示。

## エラーケース
| 条件 | 期待挙動 |
|------|----------|
| トークン失効 | 「リンクの有効期限が切れています」+ 再送導線 |
| トークン使用済み | 「既に確認済みです」+ ログイン導線 |
| 不正トークン | 「無効なリンクです」 |

## 受入基準（AC）

### AC-06-01: 正常系
```gherkin
Given users.status=email_unverified のユーザー
And 確認メールが届いている
When メール内のリンクをクリック
Then users.status が email_verified に更新される
And ダッシュボードに遷移する
And 「メールアドレスを確認しました」のフラッシュメッセージが表示される
```

### AC-06-02: 失効トークンの再送
```gherkin
Given 確認トークンが 25 時間前に発行されて失効
When ユーザーがリンクを開く
Then エラー画面に「再送する」ボタンが表示される
When 「再送する」をクリック
Then 新しい確認メールが送信される
And 旧トークンは無効化される
```

### AC-06-03: 重複確認
```gherkin
Given 既に email_verified 状態
When 古い確認リンクを開く
Then 「既に確認済みです」と表示される
And ログイン画面 / ダッシュボードへの導線が表示される
```

### AC-06-04: 再送レート制限
```gherkin
Given 1 時間以内に 3 回の確認メール再送を行った
When 4 回目の再送を試みる
Then 「しばらくお待ちください」エラー（429）
```
