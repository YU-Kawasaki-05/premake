# FR-14: スペース登録

## 概要
施設管理者（U-02）または法人管理者（U-06）が、医療機関内のアートメイク用に貸出可能なスペース（診察室・処置室・空き病室等）を登録する。

## アクター
- U-02 施設管理者
- U-06 法人管理者

## 入力データ
| フィールド | 型 | 必須 | 制約 |
|-----------|---|------|------|
| スペース名 | string | ○ | 1〜100 文字（例: "第3診察室"） |
| 部屋種別 | enum | ○ | "診察室" / "処置室" / "個室" / "病室" / "その他" |
| 広さ（㎡） | number | ○ | 1〜200 |
| 写真 | file[] | ○ | 1〜10 枚、各 10MB 以下 |
| 設備 | enum[] | × | "施術ベッド" / "拡大鏡" / "照明" / "Wi-Fi" / "洗面台" / "コンセント" / "エアコン" / "鏡" 等 |
| 備品（自由記述） | string | × | 1〜1000 文字 |
| 利用ルール | string | × | 1〜2000 文字（例: 退室時の清掃ルール、私物管理等） |
| 持ち込み可能物 | string | × | 1〜500 文字 |
| 同時施術可能人数 | int | ○ | 1〜10 |
| 入室可能時刻 | time | × | 例: 09:00（営業時間との関係） |
| 退室期限 | time | × | 例: 21:00 |
| 担当指示医（複数） | doctor_id[] | × | 当該施設に紐づく U-03 から選択（FR-18 と連動） |

## 出力 / 結果
- `spaces` テーブルに INSERT
- `status=draft` で作成（公開は FR-17）
- 写真は別 bucket、`space_images` で管理

## ビジネスルール
- BR-14-01: facility が approved 状態でないとスペース登録不可（FR-09）。
- BR-14-02: 同一施設内でスペース名重複不可。
- BR-14-03: 写真最低 1 枚必須（看護師の判断材料として）。
- BR-14-04: 担当指示医は施設の指示医（FR-18）と整合（指示医未割当のスペースは予約発生時に施設管理者が個別割当）。
- BR-14-05: スペース削除はソフトデリート（過去予約の保持）。

## エラーケース
| 条件 | 期待挙動 |
|------|----------|
| facility 未承認 | 「医療機関の審査完了後に登録できます」 |
| 写真未アップロード | 「写真を 1 枚以上アップロードしてください」 |
| スペース名重複 | 「このスペース名は既に使用されています」 |

## 受入基準（AC）

### AC-14-01: 正常系
```gherkin
Given facility (status=approved)
When U-02 が必須項目（名前 / 種別 / 広さ / 写真 / 同時施術可能人数）を入力
And 「保存」をクリック
Then spaces レコードが status=draft で INSERT される
And 写真が space_images に紐付けられる
And 「下書きとして保存しました」が表示される
And FR-17 で公開操作が可能になる
```

### AC-14-02: 設備フィルタとの連動
```gherkin
Given スペースに「施術ベッド」「拡大鏡」「Wi-Fi」を登録
When 看護師が検索（FR-19）で「拡大鏡」フィルタ
Then 当該スペースが結果に含まれる
```

### AC-14-03: 削除（ソフトデリート）
```gherkin
Given スペース S-001 に過去 5 件の予約あり
When U-02 が「削除」を選択
Then spaces.deleted_at が set される
And 過去予約は閲覧可能（保持）
And 検索結果からは除外される
```
