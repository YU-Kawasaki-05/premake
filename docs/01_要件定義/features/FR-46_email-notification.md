# FR-46: メール通知（全イベント）

## 概要
全主要イベントに対するメール通知。テンプレートエンジンで多言語対応の余地を残しつつ、β段階は日本語のみ。

## アクター
- 全認証ユーザー、利用客（ゲスト）

## 通知イベント（β段階）
| イベント | 受信者 | 優先度 |
|---|---|---|
| サインアップ確認 (FR-06) | 当該ユーザー | 高 |
| パスワードリセット (FR-05) | 当該ユーザー | 高 |
| 予約申込 (FR-21) | 看護師 + 施設 + 指示医 | 高 |
| 予約承認 (FR-22) | 看護師 | 高 |
| 予約拒否 (FR-22) | 看護師 | 高 |
| 予約キャンセル (FR-24) | 関係者全員 | 高 |
| 指示書発行依頼 (FR-28) | 指示医 | 高 |
| 指示書発行完了 (FR-29) | 看護師 | 中 |
| 施術前リマインド | 関係者 | 中 |
| 施術記録投入依頼 (FR-33) | 看護師 | 中 |
| 施術記録確認依頼 (FR-34) | 指示医 | 高 |
| 決済完了 (FR-38) | 看護師 + 施設 | 中 |
| 返金完了 (FR-40) | 受取人 | 高 |
| 利用客の予約確認 (FR-73) | 利用客 | 高 |
| アカウント凍結 (FR-11) | 当該ユーザー | 高 |

## 出力 / 結果
- メール送信（外部送信サービス: Resend / SendGrid 等。Phase 3 で確定）
- `notifications` テーブルに送信履歴
- 配信失敗・バウンスはバウンスハンドラで処理

## ビジネスルール
- BR-46-01: テンプレートはバージョン管理。変更履歴を保持。
- BR-46-02: 受信者の通知設定 (FR-48) でオプトアウト可。ただし高優先度（決済・キャンセル・凍結等）は強制送信。
- BR-46-03: 配信失敗（バウンス）時はソフト/ハードを区別。ハードバウンス連続でアカウントに警告フラグ。
- BR-46-04: メール内のリンクはユーザー固有のトークン付き（短期失効）。
- BR-46-05: メール送信は **非同期（FR-77 ジョブ）**、即時送信は重要度が高いもののみ（10 秒以内目標）。

## エラーケース
| 条件 | 期待挙動 |
|------|----------|
| 配信失敗 | リトライ（指数バックオフ）、最終失敗で運営アラート |
| ハードバウンス | 当該メールへの今後の送信停止、ユーザー設定見直しを促す |

## 受入基準（AC）

### AC-46-01: 予約承認時の即時メール
```gherkin
Given 予約 B-001 が approved
Then 看護師にメール「予約が承認されました」が 30 秒以内に届く
And 監査ログに送信記録
```

### AC-46-02: オプトアウト（任意通知）
```gherkin
Given U-01 が「予約承認通知をオフ」設定
When B-001 が approved
Then メールは送信されない
But アプリ内通知は表示される
```

### AC-46-03: 強制送信（高優先度）
```gherkin
Given U-01 がすべての通知をオフ
When 凍結 (FR-11) 発生
Then 強制的にメール送信
```

### AC-46-04: バウンス処理
```gherkin
Given メール送信失敗（ハードバウンス）
Then notifications.status=bounced 記録
And 連続 3 回ハードバウンスで users.email_bounce_flag=true
And 運営に通知
```

### AC-46-05: テンプレートバージョン
```gherkin
Given メールテンプレート v1 で送信履歴 100 件
When 運営が v2 に更新
Then 既送信メールの履歴は v1 で記録保持
And 新規送信から v2
```
