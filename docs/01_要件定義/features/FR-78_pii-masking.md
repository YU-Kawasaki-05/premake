# FR-78: 個人情報マスキング・閲覧ログ

## 概要
PII（個人情報）と医療データを含むデータの取扱を統一的に制御。デフォルトはマスキング、フル表示には閲覧理由必須 + 監査ログ。

## アクター
- システム（共通ライブラリ）
- 全認証ユーザー（マスキング適用先）

## マスキング対象
- 氏名: 「山田 H」（イニシャル化）
- メール: 「ya****@example.com」
- 電話番号: 「090-XXXX-5678」
- 住所: 番地以降をマスク
- 生年月日: 「19XX 年代」
- 看護師免許 / 医師免許画像: 概要のみ表示、フルは権限内
- 施術前後写真: 顔ぼかし（β段階は手動 / β後に AI）

## マスキングレベル（権限とコンテキストで決定）
- L0: フル表示（自分自身、自分が施術担当の利用客）
- L1: 部分マスク（同一施設の関係者）
- L2: 強マスク（法人管理者の監査用、運営の通常閲覧）
- L3: ほぼ非表示（一覧ビュー、検索結果）

## ビジネスルール
- BR-78-01: マスキングはサーバー側で適用（API 応答時にレベル決定）。クライアントから raw データに到達不能。
- BR-78-02: フル表示要求時は閲覧理由入力（運営）または当事者証明（自分の予約等）が必要。
- BR-78-03: 全フル表示閲覧は監査ログ（FR-76）に強制記録。
- BR-78-04: at-rest 暗号化: PII を含むテーブル列・写真ファイルは KMS で暗号化。
- BR-78-05: ログ・エラーメッセージへの PII 出力禁止（自動検出 + CI チェック）。
- BR-78-06: 他テナント・他ユーザーのデータが API 応答に混入していないことを RLS（Row Level Security）で保証。

## 受入基準（AC）

### AC-78-01: 一覧表示でのマスキング
```gherkin
Given 運営が一覧画面（FR-53）
Then 氏名 / メール / 電話 がマスキング表示（L2-L3）
```

### AC-78-02: フル表示時の理由入力
```gherkin
When 運営が個別ユーザー詳細を開く
Then 閲覧理由ダイアログ
When 「不正調査」と入力
Then フル表示
And 監査ログに「actor=ops, target=user_id, reason=...」記録
```

### AC-78-03: 自分のデータはフル表示
```gherkin
Given U-01 が自分のプロフィール画面
Then マスキングなしでフル表示
And 監査ログ記録は不要（自分自身）
```

### AC-78-04: at-rest 暗号化
```gherkin
When DB / S3 を直接ダンプ
Then 当該列・ファイルが暗号化されており、KMS なしには読めない
```

### AC-78-05: ログへの PII 漏洩防止
```gherkin
Given アプリケーションログ
When grep でメール形式 / 電話番号形式
Then 該当なし（マスキング済み or sanitize 済み）
```

### AC-78-06: RLS による分離
```gherkin
Given 運営以外のユーザーが API リクエスト
And 他テナントのデータを取得しようとする
Then RLS により 0 件 / 403 が返る
```
