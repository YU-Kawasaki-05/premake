# FR-80: ヘルスチェック・ステータスページ（P1）

## 概要
システム正常性の自動監視と、外部公開ステータスページ（インシデント発生時に告知）。

## アクター
- システム（監視）
- U-04 運営（インシデント告知）
- 全ユーザー（公開ステータスページ閲覧）

## 監視対象
- API サーバー（HTTP 5xx 率 / レイテンシ）
- DB（接続 / レプリケーション遅延）
- Stripe API 連携
- メール送信サービス
- SMS 送信サービス
- ストレージ（S3 / R2）
- Job キュー（DLQ 件数 / 遅延）

## 公開ステータスページ
- 各サービスの稼働状態（オンライン / 低下 / 障害）
- 過去インシデント履歴
- 計画メンテナンス予告

## ビジネスルール
- BR-80-01: 内部監視は 30 秒間隔、SLO（[仮決定]: 可用性 99.5%、p95 レイテンシ 500ms）。
- BR-80-02: 5 分連続でしきい値超過 → 運営アラート（PagerDuty / Slack 等、Phase 3 で確定）。
- BR-80-03: 公開ステータスページの更新は運営手動 + 自動（重大障害は自動降格表示）。
- BR-80-04: SLO 違反は四半期報告に含める（[仮決定]）。

## 受入基準（AC）

### AC-80-01: ヘルスチェック
```gherkin
Given DB 接続が 1 分間断続的に失敗
Then 内部アラート発火
And 5 分継続で運営に通知
```

### AC-80-02: 公開ステータスページ
```gherkin
When ユーザーが /status にアクセス
Then 各サービスの稼働状態（緑 / 黄 / 赤）が表示
And 過去 30 日のインシデント履歴
```

### AC-80-03: インシデント告知
```gherkin
Given 障害発生
When 運営が「Stripe 連携で問題発生」を投稿
Then 公開ステータスページに表示
And 関係する API レスポンスにヘッダ追加（"X-Service-Status: degraded"）
```

## サブ機能
- FR-80-1: 内部ヘルスチェック
- FR-80-2: 公開ステータスページ
- FR-80-3: インシデント告知
