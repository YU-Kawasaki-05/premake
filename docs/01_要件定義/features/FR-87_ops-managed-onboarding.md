# FR-87: 運営代理オンボーディング

## 概要
DEC-18 の 4 つ目の招待経路。運営が法人・施設・指示医・施設管理者の初期データを代理入力し、ユーザーはログインだけで利用開始できる。医療従事者の業務負担を軽減。

## アクター
- U-04 運営

## 入力データ
- 対象種別: organization / facility / facility_admin / doctor
- 各種データ（FR-13 / FR-14 / FR-82 等の入力相当）
- 担当者連絡先（メール / 電話）
- 仮パスワード（自動生成、初回ログイン時に強制変更）

## 出力 / 結果
- 該当エンティティを直接作成（pending_review or approved）
- 仮パスワード付き案内メール送信
- 初回ログイン時に強制パスワード変更（FR-02 BR-05）

## ビジネスルール
- BR-87-01: 運営は対象企業・医師の同意（書面 or メール）を確認した上でのみ実行。同意ログを保持。
- BR-87-02: 代理入力したデータは「draft」扱いで、当該ユーザーが初回ログイン時に確認・確定する。
- BR-87-03: 代理入力時は当該データに `created_by_ops=true` フラグを残し、監査時に区別可能に。
- BR-87-04: 一括 CSV インポート機能あり（複数施設・指示医を一気に登録、Phase 3 で Backoffice ツール化）。
- BR-87-05: 仮パスワードは 7 日で失効、未使用時は再発行。

## エラーケース
| 条件 | 期待挙動 |
|------|----------|
| 対象同意未確認 | 「同意確認ログをアップロードしてください」 |
| メール重複 | 「同メールで既存ユーザーがいます」 |

## 受入基準（AC）

### AC-87-01: 法人 + 配下施設 + 指示医を一括代理登録
```gherkin
Given 運営が顧客 X 社と打ち合わせ済み
When CSV テンプレートで法人 1 + 施設 3 + 指示医 5 を一括インポート
Then 各エンティティが draft 状態で作成
And 同意ログ + 仮パスワード付き案内メールが各担当者へ送信
And created_by_ops=true フラグ付与
```

### AC-87-02: 初回ログイン確認
```gherkin
Given 法人管理者の代理レコード作成済
When 当該人物が仮パスワードでログイン
Then パスワード変更ダイアログ
And プロフィール確認画面（運営入力データを表示・編集可）
And 確認後にダッシュボード遷移
```

### AC-87-03: 監査
```gherkin
When 運営が代理オンボーディング実行
Then 監査ログに完全記録
And ダッシュボードの「代理入力一覧」に表示
```

### AC-87-04: 仮パスワード失効
```gherkin
Given 仮パスワード発行から 7 日 1 時間経過
When ログインを試みる
Then 「仮パスワード期限切れ」エラー
And 「運営に連絡」or 「リセットを依頼」導線
```
