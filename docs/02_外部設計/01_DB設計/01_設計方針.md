# DB 設計 — 設計方針

> [00_index.md](00_index.md) に戻る

## 1. 命名規則

- **テーブル名**: snake_case、複数形（例: `users`, `bookings`, `treatment_records`）
- **カラム名**: snake_case
- **主キー**: `id` (UUID v7、PostgreSQL 17 / `gen_random_uuid()` で時系列順生成。β段階は v4 でも可)
- **外部キー**: `{参照テーブル単数形}_id`（例: `user_id`, `facility_id`）
- **作成時刻 / 更新時刻**: `created_at`, `updated_at` (TIMESTAMPTZ)
- **論理削除**: `deleted_at TIMESTAMPTZ NULL`（個人/施設データ系）。医療記録は物理削除しない

## 2. タイムゾーン

- DB 内は **UTC**（TIMESTAMPTZ）
- アプリ表示は Asia/Tokyo に変換

## 3. 暗号化

- **at-rest 暗号化**: Supabase Storage は標準で AES-256
- **列暗号化**: 重要 PII カラム（電子署名キー等）は `pgcrypto` で
- **署名付き URL**: 医療画像・PDF は Storage 経由で 5 分有効の署名付き URL 配信（FR-78）

## 4. 多テナント分離

- **施設テナント**: `facility_id` カラムを各業務テーブルに持たせ、RLS で分離
- **法人テナント**: `organization_id` を `facilities` に持たせ、法人配下を横断

## 5. 主要拡張機能

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;       -- 列暗号化・UUID
CREATE EXTENSION IF NOT EXISTS pg_trgm;        -- 全文検索 (空間検索)
CREATE EXTENSION IF NOT EXISTS postgis;        -- 緯度経度・距離検索 (FR-19)
CREATE EXTENSION IF NOT EXISTS pg_cron;        -- ジョブスケジューラ (DEC-26)
CREATE EXTENSION IF NOT EXISTS unaccent;       -- 検索用
```

## 6. 共通カラムテンプレート

```sql
-- updated_at を自動更新する trigger function
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

## 7. 改ざん不可テーブルのトリガー

`prescriptions`, `customer_consents`, `treatment_records`, `audit_log` は UPDATE/DELETE をトリガーで拒否する。

```sql
CREATE OR REPLACE FUNCTION reject_mutation()
RETURNS TRIGGER AS $$
BEGIN
  RAISE EXCEPTION 'Table % is append-only', TG_TABLE_NAME;
END;
$$ LANGUAGE plpgsql;

-- 例: prescriptions の UPDATE / DELETE を全拒否
CREATE TRIGGER prescriptions_no_update BEFORE UPDATE ON prescriptions
  FOR EACH ROW EXECUTE FUNCTION reject_mutation();
CREATE TRIGGER prescriptions_no_delete BEFORE DELETE ON prescriptions
  FOR EACH ROW EXECUTE FUNCTION reject_mutation();
```

> 状態遷移（例: revoke）は新規 INSERT 行で表現し、`superseded_by_*` で関係を辿る。

## 8. audit_log のハッシュチェーン

INSERT トリガーで `prev_hash` = 直前行の hash, `hash` = sha256(prev_hash || row_data) を自動計算。日次バッチで全チェーン整合性検証。

```sql
-- 概要のみ。実装詳細は 09_tables_G_運営監査.md 参照
CREATE TRIGGER audit_log_chain BEFORE INSERT ON audit_log
  FOR EACH ROW EXECUTE FUNCTION compute_audit_hash();
```

## 9. booking_sessions の二重予約防止

`EXCLUDE USING gist` で同一スペース・同時間帯の重複を防ぐ。詳細は [05_tables_C_予約顧客.md](05_tables_C_予約顧客.md) 参照。

## 10. worker_jobs の取り合い防止

`FOR UPDATE SKIP LOCKED` でワーカーが同一ジョブを取らない:

```sql
SELECT * FROM worker_jobs
WHERE status = 'pending' AND scheduled_at <= now()
ORDER BY priority DESC, scheduled_at
LIMIT 10
FOR UPDATE SKIP LOCKED;
```

詳細は [10_tables_H_横断基盤.md](10_tables_H_横断基盤.md) 参照。

## 11. RLS デフォルト方針

- **全テーブル RLS ENABLE 必須**
- **ポリシーは `../03_権限設計.md` に集約記述**（DB 設計では「RLS 適用」とのみ記載）
- Service Role は server-only Edge Function / Server Action 経由のみ使用、Client SDK は anon key
