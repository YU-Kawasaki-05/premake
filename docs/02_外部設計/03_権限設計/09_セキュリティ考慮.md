# 権限設計 — セキュリティ考慮

> [00_index.md](00_index.md) に戻る

## 1. CSRF

| 経路 | 対策 |
|---|---|
| Server Action | Next.js 標準の CSRF 対策（POST のみ + Origin 検証） |
| Route Handler (mutation) | SameSite=Lax Cookie + Origin ヘッダ検証 |
| Webhook | 署名検証（Stripe） |

## 3. レート制限

| 対象 | 制限 | 実装 |
|---|---|---|
| login / signup | IP 単位 10/min | Vercel KV (Upstash Redis) + middleware |
| パスワードリセット要求 | メール単位 5/h | DB チェック |
| SMS 送信系 | 電話番号単位 5/h | DB + Twilio quota |
| 通常 API | 認証ユーザー 600/min | Vercel KV |
| 公開検索 | 匿名 IP 60/min | Vercel KV |
| 通報 | ユーザー単位 5/day | DB チェック |

## 4. シークレット管理

### 環境変数（Vercel）
| key | scope | 用途 |
|---|---|---|
| SUPABASE_URL | server / client | 全環境 |
| SUPABASE_ANON_KEY | server / client | RLS 適用される anon |
| SUPABASE_SERVICE_ROLE_KEY | **server only** | Webhook / job / 越境操作 |
| STRIPE_SECRET_KEY | server only | Stripe API |
| STRIPE_WEBHOOK_SECRET | server only | 署名検証 |
| TWILIO_ACCOUNT_SID, AUTH_TOKEN | server only | SMS |
| RESEND_API_KEY | server only | メール |
| GUEST_SESSION_SECRET | server only | Guest JWT 署名 |
| ENCRYPTION_KEY | server only | pgcrypto 用 |
| OPS_OAUTH_ALLOWED_DOMAINS | server only | 運営ドメイン制限 |
| AXIOM_TOKEN, SENTRY_DSN | server only | 監視 |

> **絶対禁止**: `NEXT_PUBLIC_` プレフィックスでサーバー専用キーを公開すること。
> CI で grep チェック（`SUPABASE_SERVICE_ROLE_KEY` が `NEXT_PUBLIC_*` に登場したら fail）。

## 5. パスワード規則 (FR-01 BR-02)

- 12 文字以上
- 大文字 / 小文字 / 数字 / 記号 各 1 文字以上
- bcrypt cost 12 以上で保存（Supabase Auth デフォルト）
- 平文をログ・DB に残さない
- レート制限つきブルートフォース防御

## 6. セッション

- **HttpOnly Cookie** (sb-access-token, sb-refresh-token)
- **Secure** (HTTPS only)
- **SameSite=Lax**
- access_token: 1 時間有効
- refresh_token: 30 日有効
- パスワード変更 / MFA 設定変更 / 凍結時は **全セッション破棄**

## 7. データ越境（FR-78）

データアクセスの全層で防御:

| 層 | 防御策 |
|---|---|
| Application | requireRole / requireFacilityScope の徹底 |
| Database | RLS ポリシーが最後の砦 |
| Network | TLS、Supabase 側の VPC |
| Storage | Bucket policy + 署名付き URL（5 分） |

## 8. PII マスキング

`getCurrentUserMaskingLevel(target_user_id)` 関数で 4 段階のマスキングを返す:

| L | 表示 |
|---|---|
| L0 | フル（自分自身） |
| L1 | 部分 (氏名イニシャル + 電話下 4 桁) |
| L2 | 強 (氏名イニシャル + メールマスク) |
| L3 | ほぼ非表示 (一覧での表示用) |

サーバー側で適用、クライアントには raw データを送らない。

## 9. ログサニタイズ

```typescript
// アプリケーションログ用ヘルパー
function logSafely(message: string, data: unknown) {
  const sanitized = redactPII(data);  // メール/電話/カード番号を ***
  logger.info(message, sanitized);
}
```

CI で grep チェック: `email`、`phone_number`、カード番号パターンが平文出力されていないか。

## 10. 監査ログ

すべての mutation API は監査ログを残す:

```typescript
await logAudit({
  actor_id: user.id,
  action: "booking_approved",
  target_type: "booking",
  target_id: bookingId,
  details: { reason },
});
```

書き込み失敗はリクエスト全体を失敗扱い（fail-fast）。

## 11. Webhook 検証

// Twilio (status callback)
const isValid = twilio.validateRequest(AUTH_TOKEN, signature, url, body);

## 12. 暗号化

- **at-rest**: Supabase Storage AES-256（標準）、DB は pgcrypto で機微列暗号化
- **in-transit**: TLS 1.3（Vercel + Supabase 標準）
- **キー管理**: 環境変数 → 将来 Vault / KMS

## 13. 依存ライブラリの脆弱性管理

- Dependabot 有効化
- 月次で `npm audit` 実行
- 重大脆弱性は即時 patch

## 14. ペネトレーションテスト

- β リリース前に外部 ペネトレーションテスト 1 回
- 半年に 1 回（本番運用以降）
