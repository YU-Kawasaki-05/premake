## 2. 設計思想: features 単位の機能凝集

### 2.1 原則: 「この機能を消したい」ときにフォルダごと消せる構造

```
features/auth/
├── actions/        ← この機能の Server Action
├── components/     ← この機能の UI
├── hooks/          ← この機能専用フック
├── schemas/        ← この機能の zod
├── types.ts
└── index.ts        ← 公開 API（barrel）
```

### 2.2 配置判断フロー

```mermaid
flowchart TD
    A[新しいコードを書く] --> B{1 機能だけで使う?}
    B -->|Yes| C[features/{name}/ に配置]
    B -->|No| D{2 機能以上で使う?}
    D -->|Yes| E[shared/ に昇格]
    D -->|不明| F[まず features に置き、必要になったら昇格]
```

> **最初から shared に置かない**。「将来使うかも」で抽象化を増やさない（YAGNI）。

### 2.3 features 間の依存禁止

❌ NG:
```ts
import { createBooking } from '@/features/bookings/actions/createBooking';
```

✅ OK（services 経由）:
```ts
import { createBooking } from '@/services/bookings';
```

または features の `index.ts` 経由で **public API** だけ exports。

### 2.4 services 層の役割

- features に依存しない **純粋ロジック**
- Web / API / バックグラウンドジョブ / 将来モバイルから呼び出される
- Supabase クライアントは引数で受け取る（DI）

```ts
// services/bookings/createBooking.ts
import type { SupabaseClient } from '@supabase/supabase-js';

export async function createBooking(
  client: SupabaseClient,
  params: CreateBookingParams
): Promise<Booking> {
  // ビジネスロジックのみ
}
```

## 3. 命名規則

| 対象 | ルール | 例 |
|---|---|---|
| ディレクトリ | kebab-case | `nurse-pages/`, `treatment-records/` |
| TS ファイル（コンポーネント） | PascalCase | `BookingDetail.tsx` |
| TS ファイル（その他） | camelCase | `createBooking.ts`, `formatCurrency.ts` |
| Server Action 関数 | camelCase + Action | `createBookingAction` |
| Service 関数 | camelCase（動詞 + 名詞） | `createBooking`, `approveBooking` |
| zod スキーマ | camelCase + Schema | `createBookingSchema` |
| Hook | use + PascalCase | `useBookingForm` |
| Type | PascalCase | `BookingInput`, `BookingResult` |
| 定数 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 環境変数 | UPPER_SNAKE_CASE | `SUPABASE_URL` |
| テスト | `*.test.ts(x)` | `createBooking.test.ts` |
| E2E | `*.spec.ts` | `booking-flow.spec.ts` |

## 4. インポートルール

### 4.1 パスエイリアス（tsconfig.json）

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"],
      "@features/*": ["./src/features/*"],
      "@services/*": ["./src/services/*"],
      "@shared/*": ["./src/shared/*"],
      "@lib/*": ["./src/lib/*"],
      "@schemas/*": ["./src/schemas/*"],
      "@types/*": ["./src/types/*"]
    }
  }
}
```

### 4.2 import 順序（Biome / ESLint で強制）

```ts
// 1. Node / external
import { z } from 'zod';

// 2. @/lib（インフラ層）
import { createServerClient } from '@lib/supabase/server';

// 3. @services
import { createBooking } from '@services/bookings';

// 4. @schemas
import { createBookingSchema } from '@schemas/bookings';

// 5. @features / @shared
import { BookingForm } from '@features/bookings';

// 6. 相対 import（同一 feature 内）
import { localHelper } from './helpers';

// 7. type のみ
import type { Booking } from '@types/database.generated';
```

### 4.3 barrel export

- `features/{name}/index.ts` は **公開 API のみ** export
- `shared/components/ui/index.ts` は shadcn コンポーネントを集約
- それ以外は barrel 不要（tree-shake 阻害）
