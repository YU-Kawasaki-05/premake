## 2. 各サービス詳細

### 2.1 Vercel (DEC-22)
- **プラン**: Pro（$20/月）
- **使用機能**: Hosting + Server Functions + Edge Functions + Cron + Analytics + KV (Upstash Redis)
- **重要設定**: Functions Region = Tokyo (hnd1)、Edge Config 利用
- **環境変数**: 環境別 (Development/Preview/Production) で分離管理
- **制約**: Server Action 60s timeout、ファイル size 50MB max
- **代替**: Cloudflare Pages（Edge ベース、Server Actions 制約あり）

### 2.2 Supabase (DEC-21)
- **プラン**: Pro（$25/月、β）→ 本番化で Pro Plus（$599）
- **使用機能**: PostgreSQL 15 / Auth / Storage / Realtime / pg_cron / pgcrypto / PostGIS
- **重要設定**:
  - Region: Tokyo (Northeast Asia)
  - 自動バックアップ: Daily 7 日（Pro）→ 14 日（Pro Plus）
  - PITR（Point-in-Time Recovery）: Pro Plus 以降
  - PostgREST タイムアウト: 30s
- **制約**: Free tier は 500MB DB、Pro で 8GB、Pro Plus で 32GB
- **代替**: Vercel Postgres + Clerk + Cloudflare R2（個別 SaaS）

### 2.3 Stripe Connect Express (DEC-27)
- **プラン**: Connect Express（手数料 2.9% + ¥36）+ 日本の 3D Secure 対応
- **使用機能**: PaymentIntent / Authorization → Capture / Transfer / Refund / Webhook / Connect Onboarding
- **重要設定**:
  - Webhook 署名検証必須（`STRIPE_WEBHOOK_SECRET`）
  - Manual Capture（FR-22 で Authorization、FR-34 で Capture）
  - Test mode と Live mode の鍵を環境変数で分離
- **制約**: アカウント作成は本人確認必須（Stripe 側）、初回送金まで数営業日
- **代替**: GMO ペイメントゲートウェイ（国内特化）/ Square（API 機能限定的）
- **β段階の追加判断**: 看護師個別 Connect（FR-39）は Phase 4 で実装時に再検討

### 2.4 Resend + React Email (DEC-23)
- **プラン**: Free（β）→ Pro $20（〜50,000 通）
- **使用機能**: メール送信 / 添付 / トランザクションメール
- **重要設定**:
  - 独自ドメイン認証 (DKIM, DMARC, SPF)
  - From: `noreply@premake.example.com`
  - リプライ用: `support@premake.example.com`
- **代替**: SendGrid / Postmark / SES

### 2.5 Twilio Programmable Messaging (DEC-24)
- **プラン**: 従量
- **使用機能**: SMS 送信 / Verify API（OTP）
- **重要設定**:
  - 日本番号からの発信は事業者登録が必要（メッセージング サービス SID）
  - 送信失敗時の status callback でバウンス処理
- **コスト目安**: 1 通 ¥10〜15。FR-47 BR-04 のレート制限で月コスト上限を制御
- **代替**: AWS SNS（日本向けは弱い） / KDDI Message Cast（国内特化、APIの使い勝手が劣る）

### 2.6 Sentry (DEC-25)
- **プラン**: Team $26/月
- **使用機能**: エラー監視 / Performance / Release Health / Source Map
- **重要設定**:
  - `SENTRY_DSN`（Server / Client で別 DSN 可）
  - PII フィルタ（`beforeSend` で email/phone 等を除去）
  - Sampling rate: 100%（β）→ 10%（本番）

### 2.7 Axiom (Vercel ネイティブ統合)
- **プラン**: $0（〜0.5GB/月）
- **使用機能**: 構造化ログ集約 / SQL クエリで検索
- **代替**: Better Stack（旧 Logtail）/ Datadog

### 2.8 Google reCAPTCHA v3 (FR-64)
- **プラン**: $0（自動判定）
- **使用箇所**: お問い合わせフォーム / 申請フォーム
- **重要設定**: スコア閾値 0.5、超低スコアは即拒否

### 2.9 RFC 3161 タイムスタンプ (FR-29)
- **選定**: [仮決定] freeTSA.org（無料） → Phase 4 で国内 TSA に変更検討
- **代替**: SECOM TSA / NTT TSA（国内認証局、有料）
- **重要設定**: タイムスタンプトークンを `prescriptions.timestamp_token` に保存

### 2.10 Vercel KV (Upstash Redis)
- **プラン**: Free（256MB）
- **使用機能**: レート制限 / セッション補助 / フィーチャーフラグキャッシュ
- **重要設定**: 認証系・SMS 系のレート制限カウンタ
- **代替**: Upstash 直契約 / Cloudflare KV

## 5. リスクと代替策

| サービス | リスク | 代替 / 緩和策 | RISK ID |
|---|---|---|---|
| Supabase | プロジェクト障害 / 値上げ | RAW SQL マイグレーションを維持 → Postgres ベンダー移行可能 | RISK-NEW-01 |
| Stripe | 規約変更 / 国別制限 | GMO PG への切替準備（service 層で抽象化） | RISK-04（既存） |
| Vercel | function timeout 60s | 重い処理は worker_jobs 経由で分離 | RISK-NEW-02 |
| Twilio | SMS コスト爆発 | レート制限（FR-47 BR-04）+ kill_switch（運用設計） | RISK-NEW-03 |
| Resend | 配信遅延 / バウンス急増 | バウンスハンドラ実装 + SendGrid を hot-backup | - |
| TSA | サービス停止 | 複数 TSA を順番に試行（フォールバック） | RISK-NEW-04 |
| Sentry | コスト超過 | Sampling rate を本番化で 10% に絞る | - |
| Google OAuth | アカウント停止 | Supabase 標準のメール認証は常に有効に | - |

新規 RISK は `00_共通/リスク登録簿_risks.md` に追記する（Phase 9 サマリーで反映）。

## 6. サービス連携の抽象化レイヤ

将来の入れ替えに備え、各 SaaS のクライアントは `src/lib/{service}/` に閉じ込める:

```typescript
// src/lib/resend/client.ts
import { Resend } from 'resend';
import { env } from '@/env';

export const resend = new Resend(env.RESEND_API_KEY);

export async function sendEmail(params: SendEmailParams) {
  // ここで Resend 固有 API を呼ぶ
  // 将来 SendGrid 切替なら、ここだけ書き換え
}
```

> features / services 層からは `sendEmail()` を呼ぶだけ。Resend 固有 API には直接触らない。
