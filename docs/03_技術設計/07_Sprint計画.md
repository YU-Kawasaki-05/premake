# Sprint 計画・AI 駆動開発ワークフロー — premake

> 1 人 + AI エージェント開発を前提に、88 機能を Sprint に分解し、AI 指示テンプレートを整備する。

---

## 1. Sprint 運用方針

| 項目 | 設定 |
|---|---|
| 期間 | **1 週間 / Sprint** |
| 開発可能時間 | ~ 40h / Sprint（フルコミット時）、現実値は 30h |
| AI 利用方針 | **AI メイン + 人間レビュー**（DEC-26 のスピード前提） |
| タスク粒度 | **半日〜1 日** |
| 並列度 | 1（ただし AI で並行下書きはあり） |
| 完了条件 | テスト通過 + PR レビュー済（自分） + 動作確認済 |
| 計画見直し | 隔週で Backlog 再優先度付け |

## 5. AI 指示のベストプラクティス

| 原則 | 説明 |
|---|---|
| **具体的な成果物指定** | ファイル名・パスを明示 |
| **入出力を型で渡す** | zod スキーマ添付 |
| **既存ファイル参照** | 「signUp.ts のパターンに合わせて」 |
| **やらないこと明示** | スコープ宣言 |
| **1 タスク 1 指示** | 複数機能を混ぜない |
| **AC を渡す** | テスト網羅の根拠 |
| **エラーケース明示** | 422 RULE_VIOLATION 等の code 列挙 |
