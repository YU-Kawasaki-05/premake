## 1. 業務委託モデル固有の追加論点（重要度順）

### A. 偽装請負・実質雇用リスクの構造的回避

**論点**:
- 包括業務委託 + 案件アサインのモデルは「実態が雇用」と評価されるリスクがある
- 厚労省「労働者派遣事業と請負により行われる事業との区分に関する基準」(37 号告示) に照らした設計が必要

**システム設計への影響**:
- 看護師が **自己の機材・薬剤・技術** で施術していることを契約で明示・記録
- クリニック側からの「業務指示」と「医学的指示」を分離管理
- 看護師の稼働時間管理・出退勤管理を **しない** こと（雇用に近づく）
- 看護師が **他クリニックでも稼働している** ことの可視化（独立性の証拠）

**新規必要な機能候補**:
- **FR-NEW-30**: 業務委託契約の「指揮命令の独立性」を明示する条項管理
- **FR-NEW-31**: 看護師の独立事業者証明（開業届 / 個人事業主証 アップロード）
- **FR-NEW-32**: 看護師の同時稼働状況の可視化（複数クリニックでの実績ダッシュボード）

### B. 看護師の「初回オリエンテーション」フロー

**論点**:
- 新規業務委託先クリニックでの初施術前に、看護師が **院内規程・設備・緊急時対応** を把握する必要
- 法務確認資料 §4 工程 8「院内規程・衛生基準に従って施術」の前提

**必要な機能候補**:
- **FR-NEW-33**: 院内オリエンテーション完了チェック（看護師がクリニックの院内規程・緊急時対応に同意）
- 業務委託契約締結 → オリエンテーション → 初予約可能 のフロー追加

### C. 緊急時オンコール体制

**論点**:
- 法務確認資料 §5.2「医師の指示・監督」: 施術中の緊急時対応に医師がどう関与するか
- 業務委託モデルでは「医師がその場にいない」可能性が高い → オンコール体制の設計必須

**必要な機能候補**:
- **FR-NEW-34**: 緊急時連絡先テンプレート（指示医直通 / クリニック代表）
- **FR-NEW-35**: 緊急時通報ボタン（看護師ダッシュボード）→ 自動で指示医・クリニック・運営に通知
- **FR-NEW-36**: 救急搬送先の事前登録（クリニックごとに）

### D. 看護師の保険加入の必須化

**論点**:
- 法務確認資料 §6.1 「賠償責任保険」加入義務
- 業務委託モデルでは看護師個人の保険必須（クリニック側保険でカバーできない可能性）

**必要な機能候補**:
- **FR-NEW-37**: 保険加入証明書アップロード + 有効期限管理
- 期限切れ時の自動通知 + 予約制限

### E. 業務委託契約の解除と既存予約の処理

**論点**:
- 業務委託契約解除 → 当該クリニックでの **既存予約** の扱い
- 患者の自由診療契約は既に成立している → 突然のキャンセルは医療上問題

**必要な機能候補**:
- **FR-NEW-38**: 契約解除予告期間（30 日等）+ 既存予約の履行ルール
- **FR-NEW-39**: 契約解除時の既存予約の自動振替（他の契約看護師がいる場合）

### F. クリニックの倒産・閉院時の対応

**論点**:
- クリニックの倒産・閉院時に **看護師の業務委託契約・既存予約・患者情報** がどう扱われるか
- 医療情報の保存義務（7 年）はクリニック側にあるが、premake が保管している場合の扱い

**必要な機能候補**:
- **FR-NEW-40**: クリニック閉院時の医療情報引き継ぎフロー
- 法人レベルで他クリニックへの移管支援

### G. 患者の継続施術・複数回コース

**論点**:
- アートメイクは「初回 + リタッチ」のように複数回コースが一般的
- コース契約の途中で看護師が変わったり、クリニック⇔看護師契約が解除された場合の扱い

**必要な機能候補**:
- **FR-NEW-41**: 施術コース管理（複数施術を 1 セットで管理）
- 看護師変更時の患者通知・同意フロー

### H. 患者の事前カウンセリングと医師による施術可否判断

**論点**:
- 法務確認資料 §4 工程 6「医師が問診・必要情報を確認し、必要な診察・説明・施術可否判断を実施」
- 既存設計（FR-88 セッションモデル）でカウンセリング → 施術のフローは設計済
- しかし「医師による施術可否判断」の **タイミングと内容** が不明瞭

**必要な機能候補**:
- **FR-NEW-42**: 医師の事前判断フロー（問診票確認 → 施術可否判断 → 指示書発行）
- カウンセリングセッションでの医師立会いの可否（リアル / オンライン / 看護師代行）

### I. 看護師の自由診療料金設定の上限・下限

**論点**:
- 看護師ごとに自由に料金設定 → **過度に安い料金** が独禁法上の問題、**過度に高い料金** が医療広告規制上の問題
- クリニック⇔看護師間で料金が異なる場合の患者への説明

**必要な機能候補**:
- 料金設定の **目安・標準帯の表示** (premake が市場平均を提示)
- 料金変更時の **既存予約への影響** 明示

### J. プラットフォーム手数料の独占禁止法・優越的地位濫用リスク

**論点**:
- premake が 10% 手数料 + クリニック最低取り分強制 → クリニックや看護師から「優越的地位濫用」と評価されるリスク
- 特にスケール後

**システム設計への影響**:
- 料率設定の **透明性確保**（クリニック・看護師が合意の上で決定）
- 料率改定の **事前通知** 義務（90 日 等）
- 苦情窓口の明示

### K. 看護師の研修・スキルレベル管理

**論点**:
- 法務確認資料 §6.1 「研修履歴」を業務委託契約に含める
- 安全な施術のためのスキル管理（経験年数だけでなくスキル評価）

**必要な機能候補**:
- **FR-NEW-43**: 看護師の研修履歴・スキルレベル管理
- クリニック側が「最低スキルレベル要件」を業務委託契約に明記可能

### L. 法人クリニックチェーンとの契約の特殊性

**論点**:
- 法人 (U-06) 配下の複数クリニックで業務委託する場合、看護師は **法人と一括契約 vs 各クリニックと個別契約** のどちらか
- 法務的にどちらが妥当か

**必要な機能候補**:
- 法人レベルの **マスター業務委託契約** + 配下クリニックでの個別運用条件
- 法人横断の業務委託費精算

### M. 看護師の労災・社会保険

**論点**:
- 業務委託の看護師は **労災保険・健康保険・厚生年金** の対象外
- ただし施術中の事故等で看護師自身が怪我した場合のリスクをどう扱うか

**必要な機能候補**:
- 看護師の **損害保険加入推奨**（賠償責任保険 + 業務災害保険）
- premake からの推奨保険商品情報提供（紹介に止める、販売しない）

### N. 患者の予約データのポータビリティ

**論点**:
- 患者が自分の予約履歴・施術記録のエクスポートを求めた場合の対応
- 個人情報保護法 第 30 条 開示請求への対応

**必要な機能候補**:
- 患者向け **マイデータエクスポート** 機能（クリニック経由）

### O. 看護師の業務委託 → 雇用化への進化パス

**論点**:
- 業務委託で始めて、クリニックが看護師を **雇用化** したいケースが将来出る
- そのときの premake サービスとの関係性

**システム設計への影響**:
- 業務委託 → 雇用 への移行は premake サービス対象外として運用 OR
- 雇用形態でも premake の予約・記録管理を継続利用可能なオプション

## 2. 法務・コンプライアンス系の追加論点

### P. 医療法人化のタイミング

- premake 自体は医療法人ではないが、将来的に医療法人化する選択肢
- 現時点で考慮すべき: 医療法人格を取得すると **広告・サービスの範囲が変わる**

### Q. 個人情報保護委員会への届出

- 大規模な個人情報を扱う事業者として **個情委への定期報告**
- データ漏えい時の通知義務（個情法 第 26 条）

### R. 厚労省への届出

- 看護師の業務委託マッチングが「**募集情報等提供事業**」に該当する場合、届出義務
- 弁護士確認事項（法務確認資料 §5.1 質問 3）

### S. インボイス制度対応

- 看護師（個人事業主）がインボイス登録番号を持たない場合の経過措置
- premake の請求書でもインボイス対応

### T. 電子帳簿保存法対応

- 業務委託契約書・請求書・施術記録の電子保存
- 訂正・削除の証跡（タイムスタンプ）

## 3. UX・運用系の追加論点

### U. 看護師の onboarding 体験

- 新規看護師がサインアップ → 免許審査 → 業務委託契約 → 初予約まで、**ステップが増えすぎてドロップする** リスク
- 各ステップの進捗可視化、SLA、ガイダンス重要

### V. クリニックの onboarding 体験

- クリニック側も Stripe Connect 連携・院内規程整備・業務委託標準条件設定など、**やることが多い**
- マイクロステップ化、運営代理オンボーディング (FR-87) の活用

### W. β期の運営代理オンボーディングの拡張

- 業務委託契約も **運営代理で締結支援** するモデル（雛形提供 + 電子署名手配）
- β期は手動運営でカバーし、本番化で自動化

### X. 患者の問合せ窓口の明示

- 患者から問合せが来たとき「クリニックに連絡してください」と誘導する明示が必要
- ただしシステム障害は premake へ

## 4. 技術・セキュリティ系の追加論点

### Y. 医療情報安全管理ガイドライン §6.4 への対応

[厚労省 医療情報安全管理ガイドライン 第 6.0 版] への対応:
- アクセス制御（既存 RLS で対応済）
- 不正アクセス防止（既存 MFA で対応済）
- **委託契約での明示**（追加対応）
- **委託先の安全管理措置の確認**（Supabase / Vercel 等の SOC 2 / ISO 27001）

### Z. データの越境移転

- Supabase / Vercel が AWS 等のグローバルクラウド利用
- 個人情報の **海外移転に関する同意** の明示
- 同意取得タイミングと文言

### AA. ペネトレーションテストとセキュリティ監査

- 医療データ取扱で年 1〜2 回のペネトレーションテスト推奨
- SOC 2 / ISO 27001 取得の検討（コスト見合いで）

### BB. バックアップ・災害復旧の医療データ対応

- バックアップ頻度・保存場所・テスト復旧の **医療情報安全管理ガイドライン準拠**
- RTO / RPO の目標値見直し

## 5. 事業運営系の追加論点

### CC. クリニック開拓の戦略

- β段階で 1 施設 → 20 施設拡大の **クリニック開拓ストラテジー**
- 看護師の自然増 vs クリニックの自然増のバランス

### DD. 看護師ネットワークの構築

- アートメイク看護師は数千人規模 → コミュニティ・学会との連携
- インフルエンサー看護師のオフィシャル化

### EE. 保険会社との提携

- 看護師の賠償責任保険提供
- クリニックの施設賠償責任保険提供
- premake が保険会社を **紹介する**（販売しない）モデル

### FF. 教育・トレーニングの提供

- 看護師向けの **追加研修プログラム**（解剖学・色素学 等）
- premake オンライン研修の提供（差別化要素）

## 7. 思考の足跡

### 7.1 これらを書いた理由

User が「私が思いついてないだけで、出していくべき変更点がありそう」と指示。AI として **業務委託モデル特有の論点** を網羅的に整理。

### 7.2 優先度判断の基準

- **法的リスク（偽装請負・規制違反）→ 最優先**
- **患者の安全 → 高優先**
- **看護師・クリニックの実務継続性 → 中優先**
- **事業の持続性 → 中優先**
- **将来の進化パス → 低優先**

### 7.3 残された問い

- 上記の論点を **どこまで本ブランチに取り込むか** の判断は User
- 全部取り込むと工数膨大、絞ると後で課題に
- **β段階で必須** vs **本番化までに対応** vs **β後検討** の三分類で進めたい
