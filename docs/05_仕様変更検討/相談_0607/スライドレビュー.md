## 1. 現状評価（よかった点）

- **法的整理の提示構造（弁護士①②③）が明快**。「大前提 → スキーム上の指摘 → 結論」の3分割は相手に伝わりやすい。
- **主語を徹底して「私たちのスキーム」に絞っている**（スライド7 notes に明記あり）。相手のビジネスを否定しない姿勢が一貫している。
- **スライド全体のデザイン・レイアウト**は揃っており、情報密度も適切。
- **発表者ノート（aside.notes）** が各スライドに入っており、言い回しや温度感の補助として機能している。

## 2. 削除・修正が必要な箇所

### 2-A. スライド8 blockquote（最重要）

```
このままでは厳しいと受け止めています。撤退も含めて考えている、というのが正直なところです。
```

**問題**: ノートには「口頭で添える」と書かれているのに、スライド本文の `<blockquote>` として表示されている。矛盾。  
また「私達の方針・あり方」そのものの記述であり、今回削除する対象の典型。

**対処**: `<blockquote>` ごと削除。代わりに notes を充実させるか、この文は完全に口頭に任せる。

---

### 2-B. スライド11 末尾の1文

```
現場のご意見をうかがったうえで、可能性がありそうなら、将来的に試験運用や実証も検討したいと考えています。
```

**問題**: 「将来的に一緒にやりましょう」という意図の提示であり、相談事項として口頭で話す内容。スライドに書くと「押し込み」に見える。

**対処**: 削除。notes に移す。

---

### 2-C. スライド2「本日の相談」3番目の箇条書き

```
現場から見て、成立する形・現実に回るスキームがあるのかを率直に相談させてください
```

**評価**: この箇条書き自体は相談の目的として機能しており、必ずしも削除ではない。ただしスライド11「ご相談したいこと」と重複する。  
**選択肢**:
- スライド2 に残すならスライド11 を簡素化（または削除）
- スライド2 から削除してスライド11 に集約

---

### 2-D. スライド9「進めるとしたら〜」のトーン

```
その代わり、ビジネスとして成立するのかが分からない
```

**評価**: 事実として「不確かである」を伝えるのは相談の文脈で有効。ただし「分からない」だけで終わると問いかけとして弱い。  
**対処案**: 「ここが今回ヒアリングしたいポイント」という方向にリフレーム（後述の構成案参照）。

## 3. 構成の問題

### 3-A. 「当初モデル」と「業務ツールモデル」の区切りが不明瞭

現在のスライドは1〜11が連続しており、「これは過去の構想の説明」と「これは将来案」の境目が視覚的に分からない。  
相手が「今でも前のモデルでやろうとしてる？」と混乱する可能性がある。

**対処**: セクションタイトルスライドを1枚挟む。

---

### 3-B. 業務ツールモデルのパート（スライド9〜10）が薄い

「premake は予約・業務管理ツールに徹する」と書いてあるが、**具体的に何をするのかが伝わらない**。  
相手（アートメイク事業者）が「それ、うちで使えるか？」を判断できる情報量に達していない。

詳細が詰まっていない部分については「ヒアリングしながら見せる」スタイルが現実的（後述）。

## 5. 「業務ツールモデル」のスライド案

弁護士フィードバックを照合し、**グレー・NGな機能を事前に除外**した上で提示するリスト。

### 弁護士フィードバックから除外する機能

| 機能（案） | 除外理由 |
|---|---|
| **看護師の外部公開予約ページ** | 「医師を介さずに看護師が集客（患者集め）をすることはできない」— 看護師個人が患者を直接集める仕組みはNG |
| **患者→premake への直接支払い** | 「患者からpremakeに支払いをするフローは認められないのではないか」— 明示的にNG |
| **看護師が複数クリニックに機器を持ち込む管理** | 「アートメイクの機器を看護師が準備し、複数のクリニックに持ち込むことも認められない」— 機器はクリニックが管理すべきもの |
| **看護師↔患者の直接コミュニケーション機能**（相談受付・チャット等） | 「看護師が患者から直接相談を受けることも医行為の無資格実施にあたる可能性が高いことから避ける必要があります」— 相談受付・メッセージ機能は看護師→患者のルートを作るのでNG |
| **医師不在でも施術が進む予約・スケジュールフロー** | 「施術中は医師が常駐し、緊急時にも即座に対応できる体制まで必要」— 医師の常駐確認なしに施術完了できる設計はNG。医師在院の確認ステップが必須 |

> **業務委託スキーム自体への疑義（重要）**  
> 「看護師×複数クリニックの横断マッチング」的な発想に加え、弁護士は「医師の指揮命令下の業務なら業務委託ではなく雇用契約になる」と指摘。  
> また職安法改正（令和4年・改正法43条の3）により、求人情報を求職者に提供して報酬を得るスキームもNG。  
> 業務ツールモデルでは **premake はクリニック向けの管理SaaS** に徹し、集客・マッチング・紹介的な機能は一切持たない前提で見せる。

---

### 残せる機能リスト（スライドに載せる候補）

| 機能 | 内容 | 注意点 |
|---|---|---|
| 予約管理 | クリニックへの予約受付・スケジュール管理 | 主語はクリニック。看護師指名はクリニック内部の割当て |
| 問診票・同意書管理 | 患者とクリニックの間の書類を電子化 | クリニック←→患者の契約補助 |
| 指示書フロー | 医師→看護師への施術指示書（電子）| 法が求める必須フロー。**医師が指示書を出すまで施術に進めない**ガードが必要 |
| 施術記録管理 | 施術記録・写真の保管補助 | クリニックの診療録補助として |
| スタッフ管理 | 看護師の資格・シフト・担当割当 | クリニック内部の管理ツールとして |
| 報酬・給与管理補助 | 看護師への支払い・インボイス管理 | ⚠️「業務委託費」という言葉を使わない。弁護士は業務委託という枠組み自体に疑義。「報酬管理」程度の表現にとどめる |

## 6. 「ご相談したいこと」スライドの扱い

相談方針は口頭で話すとのことなので、**スライドに相談事項を書く必要はない**。  
ただし「次のセクションに移る」トリガーとして1枚あると会話の区切りになる。

**シンプル案**: スライド最後を「ここからは、ざっくばらんに教えてください」のみにして、中身は完全に口頭へ。

## 8. 作り直しの方針（まとめ）

- **削除するもの**: 「私達の立場・撤退検討・将来の協業意向」に関する本文テキスト
- **残すもの**: 当初モデルの説明・弁護士フィードバック・業務ツールモデルの骨格
- **追加するもの**: セクション見出し × 2、業務ツールモデルのスライド 1〜2 枚
- **口頭に任せるもの**: 相談方針全体（事業として回るか？試験利用の打診？）、撤退の可能性、将来の協業打診

> 業務ツールモデルの「具体的な機能」については、詳細が詰まり次第スライドを更新するか、ヒアリングしながらその場で見せる形でよい。
