## S0 — 基盤(3〜4 日)

1. スキャフォールド: Next.js(App Router, TS strict, src/)+ pnpm + Biome + Tailwind v4
2. デザイントークン(`tokens.css`、フォント: Inter + Noto Sans JP + Shippori Mincho)+ shadcn/ui 導入・再テーマ
3. `supabase init` + ローカル起動 + マイグレーション 0001〜(全 19 テーブル + btree_gist + RLS ヘルパー + ポリシー)
4. 型生成(`supabase gen types`)+ env バリデーション(@t3-oss/env-nextjs)
5. 認可ヘルパー(`requireUser` / `requireMember(clinicId, role?)` / `requireOps`)+ audit 記録ユーティリティ
6. ルーティング骨格: `(auth)` / `(app)/[clinic]` / `(public)/c/[slug]` / `(ops)`
7. CI(GitHub Actions: typecheck / biome / test / build)+ Vercel プロジェクト
8. シード(ops ユーザー + デモクリニック + サンプルメニュー・部屋)

**リスク対策**: EXCLUDE 制約(tstzrange)の動作を S0 中に検証テストで確認(重複 INSERT が 23P01 で落ちること)。

## S1 — 認証・テナント(1 週)

- ログイン / ログアウト / パスワードリセット(Supabase Auth)+ Google OAuth
- ops テナント作成画面(SCR-G01)→ owner 招待メール → 招待受諾サインアップ(SCR-A02)
- クリニック設定(SCR-F01): 基本情報・営業時間(曜日別)・定休日・公開フラグ・承認モード・キャンセル期限
- スタッフ管理(SCR-F02): 一覧・招待・ロール/雇用区分/指名可否編集
- 全 mutation の audit_logs 記録を通す

## S2 — マスタ・施術枠(1 週)

- メニュー管理(SCR-E01): セッション構成ビルダー(ステップ追加・所要時間・バッファ)、料金+表示フラグ、公開・指名可否
- 部屋・担当マトリクス(SCR-E02)
- 問診テンプレビルダー(SCR-E03): 質問型 5 種 + プレビュー
- **施術枠(schedule_blocks)**: 登録 UI(単発+曜日繰り返し一括)、重複時のエラー表示、blocked(休憩)対応
- 週ビューの簡易カレンダー(S3 台帳の土台)

## S3 — 予約台帳(1.5 週)★山場 1

- 台帳ビュー(SCR-B01): 日/週、部屋⇄スタッフレーン、枠レイヤー+予約チップ描画(仮想化は不要規模)
- 院内予約作成(SCR-B03): 患者検索→新規→メニュー→枠サジェスト(枠外警告)
- 予約詳細ドロワー(SCR-B02): ステータス遷移、セッション管理(追加・別日化)、変更・キャンセル
- ダブルブッキング防止の 3 層(UI 事前チェック / Server Action / DB EXCLUDE)
- キーボード操作・楽観的更新
- **中間デモ**: この時点でクリニックに見せられる(院内運用が回る)

## S4 — 患者・問診(1 週)

- 患者一覧・詳細(SCR-C01/02): 検索、履歴時系列、メモ、タグ
- 名寄せ: ゲスト予約→候補提示→統合(guest_* を patient に紐付け)
- 問診: 院内から記入リンク発行(トークン)→ 患者記入(SCR-P05)→ 院内閲覧(閲覧 audit)
- リタッチ運用の確認(既存予約への追加セッション)

## S5 — 公開ページ・ゲスト予約(1.5 週)★山場 2

- クリニック公開ページ(SCR-P01): 医療広告最小構成の表記設計込み
- 予約フロー(SCR-P02): 空き枠計算(blocks − sessions、メニュー刻み)、仮押さえ(30 分)、確認メール(トークン)
- 確定/承認フロー: auto=即確定 / manual=院内承認待ち一覧(SCR-B04)
- 患者側照会・変更・キャンセル(SCR-P04)
- レート制限・同時仮押さえ制限
- **法務ゲート**: 弁護士への軽い確認(単院ツール整理+公開ページ)をこの Sprint 前半に依頼(Q12)

## S6 — 通知・仕上げ(1 週)

- メール一式(React Email): 確定・変更・キャンセル・承認待ち・問診依頼・前日リマインダー
- worker_jobs 実行基盤(Vercel Cron 5 分間隔)+ 仮押さえ自動解放
- ops 利用計測(SCR-G02)
- E2E(Playwright): F1/F2/F3 の 3 フロー + 予約競合
- 法定ページ、プライバシーポリシー、クリニック向け利用契約ドラフト
- 実クリニックのデータ投入(メニュー・スタッフ・部屋 — Q9 ヒアリング結果)
