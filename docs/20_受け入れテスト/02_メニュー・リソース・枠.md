## 1. テスト範囲と前提

### 1.1 対象機能

| 要件 | 機能 | 主な画面・ルート |

> 院内アプリのルートは `/{slug}/...`(`[clinic]` セグメント = クリニック slug)。公開ページのみ `/c/{slug}/...`。本書ではデモ環境の slug = `demo` を使う。

### 1.2 前提セットアップ

- ローカル/検証環境に `supabase/seed.sql` を投入済みであること(下記アカウント・テストデータが存在する)。
- Resend(またはローカルのメールキャプチャ)が設定され、`notifications` の送信結果を確認できること(公開反映の確認で予約を作る場合)。
- Supabase ダッシュボードまたは psql で `audit_logs` / `schedule_blocks` / `services` を SQL 参照できること。
- 院内画面は PC(Chrome/Edge/Safari)。公開ページはモバイル(iOS Safari / Android Chrome)でも確認する。

## 3. テストケース詳細

### AT-CAT-001: メニュー新規作成(全属性)
- **対象要件**: v2-05
- **優先度**: P1
- **前提**: `owner@demo.local` でログイン。カテゴリ「アートメイク」が存在。
- **手順**:
  1. `/demo/services` を開く。右上「メニューを追加」をクリック。
  2. ダイアログ(タイトル「メニューを追加」)で以下を入力:
     - メニュー名: `アートメイク アイライン`
     - カテゴリ: `アートメイク`
     - 問診テンプレ: `アートメイク標準問診`
     - 説明: `医師の診察のうえ看護師が施術します。自由診療(保険適用外)です。個人差により腫れ等が生じる場合があります。`
     - 料金(円): `88000`
     - セッション構成: 既定の1ステップを「カウンセリング 30分」に変更し、「ステップを追加」で「施術 90分・バッファ 15分」を追加。
     - チェックボックス「料金を表示」「公開ページに掲載」「指名を許可」を全てオン。
  3. 「追加」をクリック。
- **期待結果**:
  - ダイアログが閉じ、一覧に「アートメイク アイライン」が追加される。行にカテゴリバッジ「アートメイク」、「公開」バッジ、「指名可」、所要「2時間15分 · ¥88,000 · 2ステップ」相当が表示される。
  - `services` に該当行が作成され、`is_public=true, show_price=true, allow_nomination=true, price_yen=88000, questionnaire_template_id` がセットされる。
  - `audit_logs` に `action='service.create'`、`target_type='service'`、`diff.name='アートメイク アイライン'` が記録される。
- **備考**: 保存成功時にダイアログは自動で閉じる。トーストは表示されない(閉じるのみ)。

### AT-CAT-004: セッション構成ビルダー(複数ステップ・並べ替え・合計時間)
- **対象要件**: v2-05
- **優先度**: P1
- **前提**: `owner@demo.local` でログイン。
- **手順**:
  1. 「メニューを追加」を開く。セッション構成で「ステップを追加」を2回押し、計3ステップにする。
  2. 各ステップの種別を「カウンセリング/施術/リタッチ」、所要を `30 / 120 / 90`、施術のバッファを `15` に設定。
  3. 3番目のステップの「▲」で2番目と入れ替え、右下「合計」表示を確認。
  4. 2番目のステップの削除(ゴミ箱)を押す。
- **期待結果**:
  - 合計表示がステップの所要+バッファの総和(例: 30+120+15+90=255 → 「4時間15分」)で更新される。
  - 「▲/▼」で順序が入れ替わる。ステップが1件になるとゴミ箱ボタンは無効化され、最後の1件は削除できない。
- **備考**: 種別ラベルは カウンセリング/施術/リタッチ/その他。ステップ表示名は任意。

### AT-CAT-005: セッション所要/バッファの境界値
- **対象要件**: v2-05
- **優先度**: P2
- **前提**: `owner@demo.local` でログイン。
- **手順**:
  1. メニュー作成でセッションの所要を `4`(下限未満)にして保存を試みる。
  2. 所要 `5`(下限)、`600`(上限)、バッファ `0`・`240` で保存できることを確認。
  3. (任意)ブラウザの開発者ツールで hidden 入力 `sessionTemplate` を `duration_min=1000` に改ざんして送信。
- **期待結果**:
  - 手順1/3のように所要 5〜600・バッファ 0〜240 の範囲外は Server Action の zod 検証で拒否され、保存されない(フォーム上部にエラー表示)。
  - 手順2は正常に保存される。
- **備考**: 数値入力欄の `min/max` はクライアント補助。サーバ側 zod(`duration_min: 5–600`, `buffer_min: 0–240`)が正。

### AT-CAT-007: 料金表示フラグの公開ページ反映
- **対象要件**: v2-05
- **優先度**: P1
- **前提**: `owner@demo.local`。公開予約=オン。
- **手順**:
  1. `/demo/services` で「アートメイク 眉」(seed は料金非表示)を確認。
  2. 別タブ(またはモバイル)で `/c/demo` を開き、「アートメイク 眉」の料金表示有無を確認。
  3. 「アートメイク 眉」を編集し「料金を表示」をオンにして保存。`/c/demo` を再読込。
- **期待結果**:
  - 院内一覧では料金は常に見える。非表示メニューは `(非表示)¥99,000` の様に「(非表示)」付きで表示される。
  - 公開ページ `/c/demo`: 手順2 では「アートメイク 眉」に金額が出ない(所要のみ)。「カウンセリングのみ ¥0」「メディカルピーリング ¥16,500」は `show_price=true` のため `¥16,500(自由診療)` の形で表示される。
  - 手順3 の後、「アートメイク 眉」にも `¥99,000(自由診療)` が表示される。
- **備考**: 公開ページの料金は必ず「(自由診療)」注記付き(医療広告・§6)。show_price=false または price_yen=null なら非表示。

### AT-CAT-011: 部屋のアーカイブ(使用中の部屋の挙動)
- **対象要件**: v2-06
- **優先度**: P1
- **前提**: `owner@demo.local`。「施術室 1」には seed の施術枠・予約が存在。
- **手順**:
  1. `/demo/rooms` で「施術室 1」を「アーカイブ」。
  2. `/demo/schedule` で「施術枠を追加」を開き、部屋の選択肢を確認。
