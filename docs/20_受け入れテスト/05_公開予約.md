# 受け入れテスト仕様書 — 公開予約(公開ページ・ゲスト予約・照会/変更/キャンセル・指名)

> 対象要件: v2-19, v2-20, v2-21, v2-22 / 作成日: 2026-07-21 / 仕様根拠: docs/10_v2_仕様/ / 状態: draft

## 1. テスト範囲と前提

### 1.1 対象機能
- **v2-19 クリニック公開ページ** `/c/{slug}`: クリニック情報・公開メニュー一覧・料金表示フラグ・自由診療の注意表記・医療提供主体の明示。症例写真/体験談なしの最小構成。
- **v2-20 ゲスト予約フロー**: メニュー →(指名 任意)→ 空き枠 → 連絡先入力 → 確認メール → リンククリックで確定。承認モードは **manual のみ**(auto は 2026-07-31 に選択肢とサーバー受け入れ値から削除。Issue #11 / PR #18)。空き枠の正しさ(open 枠・所要時間+バッファ・15分刻み・部屋/担当/既存予約の除外)。
- **v2-21 患者側予約操作**: 照会(予約番号+メール)・変更・キャンセル(トークンリンク・キャンセル期限)。
- **v2-22 施術者指名**: メニューごとの任意設定、「指定なし」既定。

### 1.2 前提セットアップ(ローカル/検証環境)
- アプリ: `pnpm dev`(http://localhost:3000)。以下 `{BASE}` = `http://localhost:3000`。
- Supabase ローカル: `pnpm db:start` → `pnpm db:reset`(`supabase/seed.sql` 投入)。REST は `http://127.0.0.1:54321`、DB は `postgresql://postgres:postgres@127.0.0.1:54322/postgres`。
- SQL 確認は Supabase Studio(http://127.0.0.1:54323)の SQL Editor か `psql "$DB_URL"` で実行。
- メール確認: 開発は `RESEND_API_KEY` 未設定でサーバーログに `[email:dev] would send { to, subject }` が出る(実送信なし)。実送信検証時は `RESEND_API_KEY` を設定し Resend ダッシュボード(Emails/Logs)で確認。**差出人表示名はクリニック名**(cron が `fromName=クリニック名` を渡す。No.21)、送信元アドレスは `EMAIL_FROM_ADDRESS` の設定値、未設定時は `onboarding@resend.dev`(本番はクリニック認証ドメインを `EMAIL_FROM_ADDRESS` に設定)。
- メール送信・前日リマインダーは Cron 経由。手動起動: `curl {BASE}/api/cron`(`CRON_SECRET` 設定時は `-H "Authorization: Bearer $CRON_SECRET"`。**本番相当(NODE_ENV≠development)で `CRON_SECRET` 未設定は 401**=SEC-01 fail-closed。開発 `pnpm dev` は未設定でもヘッダなしで実行可)。通知は作成時点で `notifications`(status=queued)に積まれ、Cron 実行で送信される。送信失敗は attempts をインクリメントし 3 回まで queued 維持で再送、以降 failed(No.20)。

### AT-PUB-005: 公開メニューのみ掲載(非公開/アーカイブ除外)
- **対象要件**: v2-19(is_public / status)
- **優先度**: P1
- **前提**: デモクリニック。任意メニュー1件を非公開化できること。
- **手順**:
  1. `{BASE}/c/demo` で現在の公開メニュー数(5件)を確認。
  2. SQL で1件を非公開化: `update services set is_public=false where id='60000000-0000-4000-a000-000000000005';`(または owner でメニュー編集画面から公開フラグをオフ)。
  3. ページを再読み込み。
  4. 別の1件をアーカイブ: `update services set status='archived' where id='60000000-0000-4000-a000-000000000004';` → 再読み込み。
- **期待結果**:
  - 手順3: メディカルピーリングが一覧から消える(4件)。
  - 手順4: カウンセリングのみも消える(3件)。
  - 非公開/アーカイブのメニューは `/c/demo/reserve?service=<非公開ID>` へ直接アクセスしても予約対象にならない(notFound で 404)。
- **備考**: 公開メニューが 0 件のときは「現在ご予約可能なメニューがありません。」と表示される。

### AT-PUB-008: 公開オフ時に全公開導線が閉じる
- **対象要件**: v2-19 / v2-03(public_booking_enabled)
- **優先度**: P0

- **手順**:
  1. owner で `{BASE}/{demo}/…` クリニック設定(SCR-F01)、または SQL `update clinics set public_booking_enabled=false where slug='demo';` で公開オフ。
