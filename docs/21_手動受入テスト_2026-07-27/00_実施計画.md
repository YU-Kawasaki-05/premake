### HTML の設計方針(納品物としての質)

- **1 ケース = 1 セクション**。ヘッダに `テスト ID / 優先度 / 判定 / 一言サマリ`
- **ステップの帯**: スクリーンショットのサムネイルを左→右に並べ、`→` で連結。各カードに「① 何をしたか」「② 何が起きたか」「③ なぜ OK と判定したか」
- サムネイルはクリックで等倍拡大(モーダル。外部ライブラリなし)
- **判定根拠を必ず併記**: 画面上の文言・DB の行・監査ログのどれで確認したかを明示する。「見た目が正しそう」で PASS にしない
- **問題が出たケースは隠さず赤で残す**。再現手順・実測値・影響範囲・暫定回避策まで書く
- デザインは `docs/60_本番移行手順/` と同じトークン(緑 `#1d5c4d` / 明朝見出し / ライト+ダーク対応)に揃える
- 冒頭に「この文書の読み方」と用語のやさしい説明(初見のチームメンバー向け)

## 4. 実行方式

**Playwright スクリプトで操作し、ステップごとに PNG と JSON を吐く**方式を採る。理由:

- 再実行できる(問題を直した後に同じ証跡を取り直せる)
- 判定を実測値から機械的に導出でき、**「実は落ちているのに OK と書く」事故を防げる**(7/26 に E2E で同種の偽陽性を踏んでいる)
- 既存の `scripts/e2e-*.mjs` の操作ロジックを流用できる

各ステップの記録フォーマット(JSON):

```jsonc
{
  "caseId": "AT-BOOK-007", "priority": "P0", "title": "既存患者検索→予約",
  "verdict": "PASS",           // PASS | FAIL | PARTIAL | NA
  "steps": [{
    "n": 1, "label": "台帳を開く",
    "action": "nurse1 でログインし /demo を開く",
    "expect": "時間×部屋グリッドが JST で描画される",
    "actual": "10:00〜19:00 の行・施術室1/2 の列を確認",
    "evidence": ["01_ledger.png"],
    "checks": [{ "kind": "dom", "detail": "…", "ok": true }],
    "ok": true
  }],
  "dbChecks": [{ "sql": "…", "expect": "…", "actual": "…", "ok": true }],
  "notes": "判定根拠の要約",
  "issues": []
}
```

**判定規約**: `verdict` はステップと DB チェックの `ok` から導出する(全 true = PASS / 1 つでも false = FAIL / 期待の一部が未実装 = PARTIAL / 環境要因で検証不能 = NA)。手書きで上書きしない。
