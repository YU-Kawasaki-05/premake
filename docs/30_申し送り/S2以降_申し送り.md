## 2. 品質・セキュリティで確立したこと

- 三層防御(proxy → requireMember/requireOps → RLS default-deny)。全業務テーブル clinic_id + `.eq` 縛り。
- 予約の二重取りは DB EXCLUDE 制約で原子的に防止(test:db でカバー)。
- ステータス遷移をサーバーで状態機械として強制(cancelled は専用処理でセッション解放)。
- 検索は PostgREST `.or` インジェクション対策(sanitizeSearchTerm)。
- 患者 PII / 問診の閲覧・検索を監査ログ化。トークンは SHA-256 ハッシュ保存。

## 3. 本番投入前にやること(優先度順)

1. **ブラウザ E2E / 手動 QA**: 当サンドボックスは `next dev/start` が SIGTERM(exit 144)で起動維持できず、クリックスルー検証が未実施。**ローカル or CI で `pnpm dev` を立てて全フロー(ログイン→設定→メニュー→施術枠→予約→公開予約→キャンセル→通知)を通す**。`scripts/e2e-s1.mjs` が Playwright の雛形。
2. **owner 不在ガードの TOCTOU 根絶**(S1レビュー持ち越し): 「最後の active owner を外せる」競合を DB トリガ/RPC で封じる。
3. **レート制限**: ログイン・ゲスト予約・照会・検索に IP/対象単位のレート制限(Upstash 等)。
4. **本番インフラ**: Vercel プロジェクト、本番 Supabase(Tokyo)、`RESEND_API_KEY`(ドメイン認証)、`CRON_SECRET`、Sentry。
5. **弁護士スポット確認**: 公開ページの医療広告(症例掲載時の限定解除)、premake の診療情報受託者としての契約条項。→ docs/06/03 Q12。
6. **メール送信元**: `lib/email.ts` の FROM をクリニック認証ドメインへ。
