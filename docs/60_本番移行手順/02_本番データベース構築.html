STEP 2 データベース構築

本番用データベース(Supabase)を東京リージョンに作り、設計図を反映します。テストデータの流し込み厳禁という最重要警告を含みます。

目安 約40分一部 開発担当者

この STEP でやること

患者・予約・スタッフのデータを保管する本番用データベース(Supabase)を作成し、アプリが使う設計図(表の構造)を反映します。最後に、アプリを動かすのに必要な3つの値(住所と鍵)を控えます。

この STEP には、開発担当者にお願いする技術的な作業と、最重要の危険警告が含まれます。必ず最後まで読んでください。

2-1. 本番 Supabase プロジェクトを作る クリニック担当者

  1. Supabase に登録・ログインブラウザで supabase.com を開き、「Start your project」からアカウントを作成します(GitHub アカウントで登録が簡単)。
  2. 新しいプロジェクトを作成「New project」を押し、プロジェクト名(例: premake-honban)を入力します。
  3. リージョンは「Tokyo (Northeast Asia / ap-northeast-1)」を選ぶデータの保管場所です。必ず東京(Tokyo)を選んでください。国内のクリニックからのアクセスが速く、データも国内に置けます。
  4. データベースのパスワードを強力に設定して控える自動生成される強いパスワードを使い、パスワード管理ツールに保存します。これは後で設計図の反映に使います。
  5. 作成し、準備完了まで数分待つ「Create new project」を押すと、データベースの用意に1〜2分かかります。

2-2. 【最重要】テスト用初期データを本番に流さない 開発担当者と共有

⚠本番のデータベースに seed(シード)を絶対に流し込まないこと

このアプリには開発・動作確認のためのテスト用初期データ(ファイル名 supabase/seed.sql)があります。この中には、「premake-dev」という誰でも知っているパスワードの管理者(全権)アカウントや、架空のデモクリニック・架空の患者が含まれています。

これを本番データベースに入れてしまうと、外部の誰でもその公開パスワードで管理者としてログインできる『裏口(バックドア)』ができ、患者情報の漏えいにつながります。実在患者の情報を扱う本番では、絶対に流し込まないでください。

✓正しいやり方: 設計図(マイグレーション)だけを反映する

次の 2-3 で使う supabase db push というコマンドは、空の設計図(表の構造)だけを反映し、テストデータは入れません。これが本番の正しい手順です。

やってはいけないのは次の2つです:

  • supabase db reset を本番(--linked)に対して実行する — データを全消去し seed を流します。厳禁。
  • Supabase 画面の「SQL Editor」に seed.sql の中身を貼り付けて実行する。厳禁。

2-3. 設計図(マイグレーション)を反映する 開発担当者

ここは開発担当者にお願いする作業です(パソコンでコマンドを実行します)。アプリのプログラム(リポジトリ)を開いた状態で、次を順に実行します。

ⓘコマンドが使えないときの代替手段(開発担当者向け)

CLI が使えない場合は、Supabase 画面の「SQL Editor」で、supabase/migrations/ フォルダ内の SQL ファイルをファイル名の順番どおりに開いて中身を貼り付け・実行してください(現在は 20260707000001_init.sql → 20260722000001_cancel_booking_atomic.sql の順)。seed.sql は含めないこと。

2-4. 最初の管理者(ops)アカウントを手作業で1つだけ作る クリニック担当者

premake では、「ops(運営)」という管理者が、クリニックと院長アカウントを作成します。この ops アカウントだけは、まだ誰も存在しないため手作業で1つ用意します(2人目以降・院長・看護師は、後の STEP 6 で招待リンクから作るので手作業は不要です)。

  1. Supabase でユーザーを追加Supabase 画面 → 左メニュー「Authentication」→「Users」→「Add user」→「Create new user」。運営用のメールアドレスと強いパスワードを入力し、「Auto Confirm User(自動で確認済みにする)」にチェックして作成します。このメールとパスワードは大切に保管してください。
  2. そのユーザーを『運営(ops)』に昇格させるSupabase 画面 → 左メニュー「SQL Editor」→「New query」に、下のコマンドを貼り付けて実行します。

⚠この管理者アカウントの扱い

この ops アカウントは全クリニックを管理できる強力な権限を持ちます。パスワードは絶対に共有・使い回しをせず、パスワード管理ツールに保管してください。

2-5. ログインの URL 設定を本番用にする クリニック担当者

パスワード再設定メールなどのリンクが正しく動くよう、Supabase にアプリの本番 URL を教えます(この設定をしないと、リンクが localhost ＝手元のパソコンを指してしまい、開けません)。

ⓘアプリの URL がまだ決まっていない場合

この設定はアプリの本番 URL が必要です。STEP 3 でアプリを公開して URL が決まってから、ここに戻って設定しても構いません。忘れないようチェックリストに入れてあります。

  1. URL 設定を開くSupabase 画面 → 「Authentication」→「URL Configuration」。
  2. Site URL に本番 URL を入れる例: https://your-clinic.vercel.app(STEP 3 で決まる URL)。
  3. Redirect URLs に折り返し先を追加https://(本番URL)/auth/callback と https://(本番URL)/reset-password/update を追加します。

2-6. アプリに渡す「3つの値」を控える クリニック担当者

次の STEP 3 で使う大切な値です。Supabase 画面 → 「Project Settings」→「API」で確認できます。メモ帳ではなくパスワード管理ツールに保管してください。

控える値どこにある?役割
Project URLAPI 設定の「Project URL」データベースの住所
anon public キーAPI 設定の「Project API keys」→ anon public一般アクセス用の鍵(公開されてよい鍵)
service_role キーAPI 設定の「Project API keys」→ service_role全権の秘密鍵。絶対に外部に出さない

⚠service_role キーは最重要の秘密

この鍵はデータベースの全操作ができます。メール・チャット・スクリーンショットで共有しない、公開の場に貼らないでください。次の STEP で Vercel の環境変数に登録する以外の用途では使いません。
