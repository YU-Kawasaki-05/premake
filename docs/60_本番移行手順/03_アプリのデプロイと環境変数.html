STEP 3 デプロイと環境変数

アプリを Vercel でインターネットに公開し、動作に必要な環境変数(設定値)を登録します。未設定だと公開自体ができない APP_URL、メールが1通も届かなくなる CRON_SECRET が特に重要です。

目安 約40分クリニック担当者

この STEP でやること

アプリ本体を Vercel でインターネットに公開(デプロイ)し、動作に必要な環境変数(設定値)を登録します。ここまで来ると、ブラウザからアプリのログイン画面が開けるようになります。

環境変数は全部で7つあります。うち5つは必須(足りないと公開できない、またはメールが届かない)、残る2つはメール関連で次の STEP 4 で登録します。

3-1. Vercel にアプリを公開する クリニック担当者

  1. Vercel に登録・ログインvercel.com でアカウント作成。アプリのプログラムがある GitHub アカウントで登録すると連携が簡単です。
  2. プロジェクトを取り込む(Import)「Add New… → Project」から、アプリのリポジトリ(開発担当者に確認)を選び「Import」。
  3. 設定はそのままでよいFramework は自動で「Next.js」と認識されます。ビルド設定は既定のままで構いません(この段階では「Deploy」を押す前に、次の 3-2 の環境変数を先に入れると手戻りが減ります)。

☞先に環境変数を入れるのがコツ

アプリは環境変数がそろって初めて正しく動きます。3-2 の環境変数を登録してから「Deploy」を押すと、1回で正しく公開できます。

逆に、何も登録せずに「Deploy」を押すと必須の設定が足りないため公開に失敗します。これは故障ではなく、設定漏れに気づかせるための正常な動きです(詳しくは 3-4)。もし先に押してしまっても、3-2 を登録してから「再デプロイ(Redeploy)」すれば公開できます。

3-2. 環境変数(設定値)を登録する クリニック担当者

Vercel のプロジェクト → 「Settings」→「Environment Variables」で、下の表の値を1つずつ登録します。対象環境は Production(本番) にチェックを入れてください。「名前(Key)」は一字一句そのまま正確に入力します。

⚠NEXT_PUBLIC_ で始まる2つは「公開後」に変えたら再デプロイが必要

NEXT_PUBLIC_... の2つの値は、アプリを組み立てる時(ビルド時)に埋め込まれます。後から変更した場合は、Vercel の「Deployments」→ 最新 → 「Redeploy」で作り直してください。

3-3. CRON_SECRET を設定する(未設定だとメールが1通も届きません)

CRON_SECRET は、定期実行を『関係者以外が呼び出せない』ようにする合言葉です。ここで「定期実行」とは、アプリが1時間ごとに自動で行うメールの送信作業のこと。premake では、予約確認・変更・キャンセル・院内へのお知らせ・前日リマインダーのすべてのメールが、いったん送信待ちの列に並び、この定期実行がまとめて送る仕組みになっています。

⚠未設定のまま公開すると、メール機能が全滅します(SEC-01)

本番では、この合言葉が設定されていないと、定期実行の入口がすべて拒否されます(安全側に倒す設計 = fail-closed)。その結果、前日リマインダーだけでなく、予約確認メールもキャンセル通知も、院内への「新しい予約が入りました」も、1通も送られません。メールは送信待ちの列に溜まり続けます。

逆に、空欄や secret のような弱い値にすると、第三者が定期実行を勝手に呼び出せてしまい、大量のメール送信などを誘発されるおそれがあります。必ず長くて推測できない値を設定してください。

長いランダム文字列の作り方(どちらか1つでOK)

  • 方法A: パスワード管理ツールの生成機能を使う(クリニック担当者だけで完結します) — 1Password や Bitwarden などの「新しいパスワードを生成」機能で、記号なし・40文字以上の英数字を作り、それをそのまま値として貼り付けます。作った値は同じツールに保管してください。
  • 方法B: 開発担当者にコマンドで作ってもらう — 下のコマンドを1回実行し、出てきた文字列を貸してもらいます。

⚠この値の扱い

合言葉なのでパスワードと同じ扱いです。メールやチャットに貼らず、パスワード管理ツールに保管してください。人が覚える必要はありません(入力するのは Vercel への登録時の1回だけです)。

ⓘうれしい仕組み

Vercel は、CRON_SECRET を環境変数に登録しておくと、定期実行のときに自動でこの合言葉を付けてアプリを呼び出します。つまり値を登録するだけで、正規の定期実行は通り、部外者は弾かれる状態になります。別途どこかに合言葉を入力する作業はありません。

定期実行がちゃんと動いているかの確認方法は STEP 5「定期実行(リマインダー)の確認」で扱います。

3-4. APP_URL は本番では必須(未設定だと公開できません)

APP_URL は、メール内のリンク・スタッフ招待リンク・パスワード再設定リンクを組み立てる時の土台になる URL です。ここが本番 URL になっていないと、手元の練習用アドレス http://localhost:3000 を指すリンクが送られてしまい、患者やスタッフは受け取ったリンクを開けません。

⚠未設定なら、アプリは公開の時点で止まります(わざとそうしています)

この事故を防ぐため、premake は本番では APP_URL を必須にしています。未設定のまま公開しようとすると、公開の準備(ビルド)または起動の時点でエラーになり、そこで止まります。「気づかないまま localhost 宛のリンクを患者に送り続ける」より、最初にはっきり止まったほうが安全だからです(このような設計を fail-fast = 早く失敗させる、と呼びます)。

つまり「エラーで公開できない」場合は、故障ではなく設定漏れのお知らせです。値を登録して「Redeploy」すれば公開できます。

☞入れる値の形

https:// から始まる本番 URL をそのまま入れます(例 https://your-clinic.vercel.app)。末尾に / は付けないでください。リンクを組み立てるときに / が二重になってしまいます。独自ドメイン(例 https://reserve.クリニック.jp)を使う場合は、患者に案内する側の URL を入れてください。

3-5. EMAIL_FROM_ADDRESS(メールの差出人アドレス)

患者に届くメールの差出人に関わる設定です。差出人の表示名は自動でクリニック名になります(この部分に設定作業は要りません)。EMAIL_FROM_ADDRESS で指定するのは、その隣に表示されるメールアドレスの部分です。

差出人の見え方患者から見た印象
未設定クリニック名 <onboarding@resend.dev>メール会社(Resend)の共有テスト用アドレスのため、迷惑メールに振り分けられやすく、届かないことがあります
設定済み(推奨)クリニック名 <reserve@クリニックのドメイン>クリニック自身のアドレスから届くため信頼されやすく、到達率も上がります

ⓘ設定は STEP 4 とセットで行います

このアドレスを使うには、そのドメインが自分のものであることをメール会社に証明する手続き(ドメイン認証)が必要です。手順は次の STEP 4「メール送信の設定」で扱いますので、ここでは空のままでも構いません。STEP 4 でアドレスが決まったら、この環境変数に登録して「Redeploy」してください。

ドメイン認証をしていないアドレスを入れると、かえってメールが送れなくなります。必ず STEP 4 の認証を済ませてから登録してください。

3-6. デプロイして動作を確認する

  1. Deploy(または Redeploy)環境変数を登録したら公開します。数分でビルドが終わります。
  2. 本番 URL を開く発行された URL(例 https://your-clinic.vercel.app)をブラウザで開きます。
  3. ログイン画面を確認URL の末尾に /login を付けてログイン画面が表示されれば、公開は成功です。STEP 2 で作った ops アカウントでログインを試せます(ログイン後は /ops でクリニック管理画面へ)。

☞任意: 応答を速くする

Vercel のプロジェクト設定で、サーバー処理の地域(Function Region)を Tokyo(hnd1) にすると、東京の Supabase との通信が速くなります(必須ではありません)。
