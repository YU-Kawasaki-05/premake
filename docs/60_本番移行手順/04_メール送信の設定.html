STEP 4 メール設定

予約確認や前日リマインダーのメールを実際に送れるようにします。差出人の名前はクリニック名が自動で入るようになったため、この STEP は Resend の登録・ドメイン認証・差出人アドレスの登録という設定作業だけで完了します。

目安 約30分一部 開発担当者

この STEP でやること

予約の確定・受付・変更・キャンセル・前日リマインダーといったメールを実際に送れるように設定します。やることは 3 つだけです。

  • メール送信サービス Resend のアカウントを作り、鍵(API キー)を Vercel に登録する
  • クリニックのドメインを 認証する(SPF / DKIM。迷惑メール扱いを避けるための設定)
  • 差出人のアドレス(EMAIL_FROM_ADDRESS)を Vercel に登録する

✓プログラムの修正は、もう必要ありません

以前の手順書では「差出人がクリニック名にならないので、開発担当者にプログラムを直してもらう必要がある」とご案内していました。現在はアプリ側で対応済みです。メールの差出人の名前には、設定画面「クリニック設定 → 基本情報」のクリニック名がそのまま入ります。この STEP は設定作業だけで終わります。

ⓘメールを設定しないとどうなる?

RESEND_API_KEY が未登録の間は、アプリはメールを実際には送りません(サーバーの記録に「送ろうとした」と残るだけで、患者には届きません)。予約確認やリマインダーを届けるには、この STEP が必要です。

4-1. Resend アカウントと API キー クリニック担当者

  1. Resend に登録resend.com でアカウントを作成します。
  2. API キーを作成左メニュー「API Keys」→「Create API Key」。名前(例 premake-honban)を付けて作成し、表示された鍵をコピーします(この画面を閉じると二度と表示されません。パスワード管理ツールに保存してください)。
  3. Vercel に登録STEP 3 と同じ手順で、環境変数 RESEND_API_KEY にこの鍵を登録し、再デプロイします(環境変数は再デプロイして初めて反映されます)。

4-2. ドメイン認証(SPF / DKIM)クリニック担当者

ドメイン認証とは、「このメールは本物のクリニックから送られたものだ」と受信側に証明するための設定です。これをすると、差出人をクリニックのドメイン(例 reserve@your-clinic.jp)にでき、迷惑メールフォルダに入りにくくなります。独自ドメインをお持ちの場合に行ってください。

  1. Resend にドメインを追加「Domains」→「Add Domain」で、お持ちのドメイン(例 your-clinic.jp)を入力します。
  2. 表示された DNS レコードを控えるType(種類)/ Name(名前)/ Value(値)が数行の表で表示されます。Type は TXT か CNAME です。これがこの STEP でいちばん難しい部分なので、あわてずに 1 行ずつ進めてください。
  3. ドメイン管理会社の画面に貼り付けるドメインを買った会社(お名前.com・さくらインターネット・Cloudflare 等)にログインし、「DNS 設定」「DNS レコード設定」といったメニューを開きます。「レコードを追加」から、Resend の表と同じ Type・Name・Value を 1 行ずつ登録し、保存します。
  4. Resend で「Verify」を押して待つResend のドメイン画面で「Verify DNS Records」を押します。表示が Verified(認証済み)になれば完了です。反映には数分〜数時間(会社によっては最大 1〜2 日)かかることがあります。すぐに Verified にならなくても、しばらく待ってからもう一度押してください。

⚠貼り付けるときに間違えやすい 3 点

1. Name の二重入力 — 管理会社の画面では、Name 欄に自動でドメイン名が付く場合があります。その場合 resend._domainkey.your-clinic.jp ではなく resend._domainkey の部分だけを入力します(.your-clinic.jp が二重になると認証されません)。

2. 前後の空白・改行 — コピー&ペースト時に余分な空白や改行が入ると認証に失敗します。貼り付けたあと、値の先頭と末尾を確認してください。

3. 既存のメール設定との衝突 — すでに同じドメインでクリニックの通常メールを使っている場合は、必ず開発担当者かドメイン管理会社に相談してください。SPF の設定は 1 つのドメインに 1 行しか置けないため、既にある行を消して追加してしまうと、クリニックの普段のメールが届かなくなることがあります。

☞SPF・DKIM をやさしく言うと

SPF=「このドメインのメールは Resend が代理で送ってよい」という許可証。DKIM=メールに付ける「改ざんされていない」という電子印鑑。どちらもドメインの持ち主だけが設定でき、受信側が本物か確認するのに使われます。

ⓘむずかしければ丸ごとお願いしてかまいません

Resend の DNS レコード画面のスクリーンショットと、ドメイン管理会社の名前を開発担当者に渡せば代行できます。ここで無理をして既存の設定を壊すより安全です。

4-3. 差出人アドレスを登録する(EMAIL_FROM_ADDRESS)クリニック担当者

4-2 で認証したドメインのメールアドレスを、環境変数 EMAIL_FROM_ADDRESS に登録します。これで患者に届くメールの差出人が、クリニックのアドレスになります。

実際に患者へ届くメールの差出人は、クリニック名(設定画面の基本情報)と、このアドレスを組み合わせた形になります。

EMAIL_FROM_ADDRESS患者に見える差出人到達性
認証済みドメインのアドレスを登録
例 reserve@your-clinic.jp		さくらクリニック <reserve@your-clinic.jp>良い(推奨)
未登録のままさくらクリニック <onboarding@resend.dev>低い。Resend の共有テスト用ドメインから送られるため、迷惑メール扱いされやすくなります

⚠順番を間違えないでください

認証(Verified)が済んでいないドメインのアドレスを登録すると、Resend が送信を拒否し、メールが 1 通も届かなくなります。必ず 4-2 で Verified になったことを確認してから登録してください。ドメインをお持ちでない場合は、当面この項目を空のままにして運用を始めることもできます(到達性は下がります)。

☞受信できるアドレスにしておくと安心です

患者がメールに「返信」すると、この差出人アドレスに返信が届きます。そのため、誰かが受信を確認できるアドレス(受付の共有メールなど)を指定しておくのがおすすめです。誰も見ないアドレスにすると、患者の返信に気づけません。

4-4. どんなメールが送られるのか

アプリが送るメールは7 種類です。患者向けが 5 種類、院内(クリニック)向けが 2 種類あります。院内向けは今回新しく追加されたもので、Web 予約の見落としを防ぐためのお知らせです。

患者向け(5 種類)

種類件名送られるとき
確定【クリニック名】ご予約が確定しました院内の台帳で予約を作成したとき／承認待ちの予約を「確定にする」で承認したとき
受付【クリニック名】ご予約を受け付けました(確認中)公開ページから予約が入り、院内の承認を待っているとき(承認モードが「院内で承認する」の場合)
変更【クリニック名】ご予約内容が変更になりました台帳で「予約を変更」を行い、日時・担当・部屋を変えたとき
キャンセル【クリニック名】ご予約をキャンセルしました院内でキャンセルしたとき／患者が自分でキャンセルしたとき
リマインダー【クリニック名】ご予約日のお知らせ定期実行が来院予定の予約を見つけたとき(STEP 5)

件名と差出人名の「クリニック名」は、設定画面「クリニック設定 → 基本情報」のクリニック名がそのまま使われます。メールアドレスが登録されていない患者(電話予約のみ 等)には送られません。これは正常な動作です。

院内向け(2 種類・新規)

種類件名送られるとき
院内新規【予約システム】新しい予約が入りました(要確認)公開ページから予約が入ったとき。本文に「承認操作が必要か」も書かれています
院内キャンセル【予約システム】予約がキャンセルされました患者が自分でキャンセルしたとき。枠が空いたことをお知らせします

ⓘ院内向けメールの宛先は「基本情報のメールアドレス」です

院内向けのお知らせは、設定画面「クリニック設定 → 基本情報」の「メールアドレス」に届きます。ここが空欄の場合は、院長(オーナー)のログイン用メールアドレスに送られます。どちらも登録がないと院内向けメールは送られませんので、STEP 6 の初期設定で必ず入力してください。受付が毎日確認できる共有アドレスにするのがおすすめです。

✓メール本文の安全対策も実装済みです

以前の手順書で「未対応」としていたメール本文の差し込み値の安全処理(エスケープ)は実装済みです。患者が入力した名前などに記号が含まれていても、本文の表示が崩れたり、悪意のあるリンクが差し込まれたりしません。本文に載せるリンクも、正しい形の URL でなければ載せない仕組みになっています。

4-5. 送信に失敗したときの動き(自動再送)

メールの送信は、相手のサーバーが混んでいるなどの理由で一時的に失敗することがあります。この場合、アプリは自動でやり直します。

状態の表示意味と、必要な対応
待機中送信の順番待ちです。次の定期実行で送られます(最大およそ 1 時間後)
送信中いま送信処理をしています。通常はすぐ「送信済み」に変わります
送信済み正常に送れました。対応は不要です
失敗3 回やり直しても送れなかったものです。これ以上は自動で送られません。アドレスの打ち間違いが多いので、患者の連絡先を確認し、必要なら電話などで直接ご連絡ください

⚠「失敗」は自動では送り直されません

一時的な失敗は最大 3 回まで自動でやり直しますが、3 回で送れなかったものは「失敗」として記録されたままになります。アプリが後で勝手に送り直すことはありません。気づかないまま放置しないよう、定期的な確認が必要です。

送信の結果は、院内の設定画面「クリニック設定 →『通知の送信状況』」(院長のみ表示)で確認できます。直近 50 件について、種類・宛先・状態・やり直した回数・エラー内容・日時が一覧で表示されます。週に 1 回ここを見て「失敗」がないか確認する運用をおすすめします。確認の頻度や手順は STEP 8 運用とバックアップ をご覧ください。

4-6. テスト送信の確認

メールが実際に届くかは、次のように確認します(メールは定期実行のタイミングで送られます。仕組みは STEP 5)。

  1. 自分宛の予約を 1 件つくるSTEP 6 まで進んだあと、自分のメールアドレスを登録した患者でテスト予約を 1 件作成します。
  2. 定期実行を 1 回動かすメールは定期実行がまとめて送ります。すぐに確認したい場合は、STEP 5 の「手動で 1 回動かす」を使います。
  3. 受信を確認する自分の受信トレイに「ご予約が確定しました」が届くか確認します。迷惑メールフォルダも必ず確認してください。
  4. アプリと Resend の記録を確認する設定画面の「通知の送信状況」が送信済みになっているか、Resend 画面の「Logs」が Delivered(配信済み)になっているかを見ます。差出人がクリニック名になっていることも、ここで一緒に確認できます。
