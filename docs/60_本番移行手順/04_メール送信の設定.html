STEP 4 メール設定

予約確認や前日リマインダーのメールを送れるように、Resend の設定とドメイン認証、送信元をクリニック名にする作業を行います。

目安 約30分一部 開発担当者

この STEP でやること

予約確認・キャンセル・前日リマインダーのメールを実際に送れるように設定します。メール送信サービス Resend のアカウント作成、鍵の取得、ドメイン認証、そして送信元をクリニック名にする作業を行います。

ⓘメールを設定しないとどうなる?

RESEND_API_KEY が未設定の間は、アプリはメールを実際には送りません(内部の記録に「送ったつもり」と残るだけ)。患者への予約確認やリマインダーを届けるには、この STEP が必要です。

4-1. Resend アカウントと API キー クリニック担当者

  1. Resend に登録resend.com でアカウントを作成します。
  2. API キーを作成左メニュー「API Keys」→「Create API Key」。名前(例 premake-honban)を付けて作成し、表示された鍵をコピーします(この画面を閉じると二度と表示されません。パスワード管理ツールに保存)。
  3. Vercel に登録STEP 3 の環境変数 RESEND_API_KEY にこの鍵を設定し、再デプロイします。

4-2. ドメイン認証(SPF / DKIM)クリニック担当者

ドメイン認証とは、「このメールは本物のクリニックから送られた」と証明する設定です。これをすると、送信元をクリニックのドメインにでき、迷惑メール扱いされにくくなります。独自ドメインをお持ちの場合に行います。

  1. Resend にドメインを追加「Domains」→「Add Domain」で、お持ちのドメイン(例 your-clinic.jp)を入力します。
  2. 表示された DNS レコードをドメイン管理画面に貼るSPF・DKIM という数行の設定値が表示されます。これを、ドメインを買った会社(お名前.com・Cloudflare 等)の「DNS 設定」画面に、表示どおりコピーして追加します。むずかしければ、この画面のスクリーンショットを開発担当者に渡してください。
  3. 認証(Verify)を待つ設定が反映されると Resend の画面が「Verified(認証済み)」になります(数分〜最大で数時間かかることがあります)。

☞SPF・DKIM をやさしく言うと

SPF=「このドメインのメールは Resend が代理で送ってよい」という許可証。DKIM=メールに付ける「改ざんされていない」という電子印鑑。どちらもドメインの持ち主だけが設定でき、受信側が本物か確認するのに使われます。

4-3. 送信元をクリニック名にする 開発担当者

⚠現状は送信元が「premake」の仮アドレスのままです(要・コード修正)

今のアプリは、メールの送信元が premake <onboarding@resend.dev> という開発用の仮の値に固定されています(プログラム内 src/lib/email.ts)。このままでは、患者に届くメールの送信元がクリニック名にならず、迷惑メールにも入りやすくなります。

本番前に開発担当者にお願いして、送信元を 4-2 で認証したクリニックのドメイン・クリニック名に書き換えてもらってください。例: 〇〇クリニック <yoyaku@your-clinic.jp>。認証済みドメイン以外の送信元は Resend が拒否します。

ⓘ開発担当者へのメモ

src/lib/email.ts の FROM 定数を、認証済みドメインの差出人に変更(理想はクリニック名を環境変数化)。返信先(replyTo)にクリニックの問い合わせ先を入れる運用も検討してください。併せて、メール本文の差し込み値の HTML エスケープ(未対応事項参照)も確認を推奨します。

4-4. テスト送信の確認

メールが実際に届くかは、次のように確認します(定期実行の仕組みは STEP 5 で扱います)。

  1. 自分宛の予約を1件作るSTEP 6 まで進んだ後、テスト用に自分のメールアドレスを登録した患者で予約を1件作成します。
  2. 定期実行を1回動かすメールは定期実行のタイミングで送られます(STEP 5)。手動で動かして確認する方法は STEP 5 に記載します。
  3. 受信を確認 / Resend の記録を見る自分の受信トレイに確認メールが届くか、また Resend 画面の「Logs」で送信結果(Delivered=配信済み)を確認します。
