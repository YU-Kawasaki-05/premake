STEP 5 定期実行の確認

メール送信と前日リマインダーを自動で動かす『定期実行』が、本番で正しく動くことを確認します。合言葉(CRON_SECRET)が未登録だと定期実行が一切動かないため、ここは必ず確認してください。

目安 約20分確認中心

この STEP でやること

前日リマインダーやメール送信を自動で定期的に動かす仕組み(定期実行)が、本番で正しく動くことを確認します。新しく作る設定はほとんどなく、『動いているかの確認』が中心です。ただし 5-2 の合言葉の確認は必須です。

5-1. メールが届く仕組み(大事な前提)

premake では、確認・変更・キャンセル・リマインダーのメールはすぐには送られません。いったん送信予約リスト(キュー)にためられ、『定期実行』がまとめて送信します。予約の登録処理を、メール送信の失敗で止めないための仕組みです。

タイミング起きること
予約作成・変更・キャンセルなどメールが送信予約リスト(キュー)に積まれる(状態=待機中)
定期実行(/api/cron)が動く① 前日リマインダーを作る → ② たまったメールをまとめて送信(状態=送信済み)

ⓘつまり「メールの遅れ」は定期実行の間隔と同じ

このアプリの定期実行は1 時間ごと(毎時 0 分)に設定されています(設定ファイル vercel.json の 0 * * * *)。そのため、予約確認メールは作成から最大およそ 1 時間後に届きます。これは仕様です。リアルタイム送信ではない点を、運用でご理解ください。

⚠Vercel のプランに注意(重要)

1 時間ごとの定期実行を動かすには、Vercel の有料プラン(Pro)が必要です。無料プラン(Hobby)では定期実行が1 日 1 回までに制限され、予約確認メールが最大 1 日遅れるため、クリニック運用には向きません。本番運用の前に Vercel Pro への切り替えを推奨します。

5-2. 合言葉(CRON_SECRET)の確認 — 必須

⚠未登録だと、定期実行が全部拒否されます

CRON_SECRET が本番環境に登録されていないと、定期実行の呼び出しはすべて「権限なし(401)」で拒否されます。その結果、予約確認メールもリマインダーも 1 通も送られません(予約自体は正常に登録されますが、メールが待機中のままたまり続けます)。

これは安全のためにわざとそうしている設計です。合言葉なしで動く状態だと、外部の誰でも定期実行を呼び出せてしまうため、「合言葉がなければ動かさない」という判断になっています。「未登録でもとりあえず動く」わけではありません。

  1. Vercel の環境変数を確認するVercel のプロジェクト →「Settings」→「Environment Variables」で CRON_SECRET がProduction(本番)に登録されているかを確認します。STEP 3 で登録済みなら、ここは確認だけで済みます。
  2. 未登録なら、長いランダムな文字列を作って登録する推測されない長さ(32 文字以上)の英数字にします。パスワード管理ツールの「パスワード生成」機能で作るのが手軽です。開発担当者がいる場合は、下のコマンドでも作れます。
  3. 登録したら再デプロイする環境変数は再デプロイして初めて反映されます。登録しただけでは有効になりません。

ⓘ合言葉は自分で入力する必要はありません

CRON_SECRET を登録しておけば、Vercel が定期実行のたびに自動でこの合言葉を付けて呼び出します。日々の運用で誰かが入力する作業はありません。手で動かして確認したいときだけ、5-6 の「方法C」で使います。

5-3. 前日リマインダーの仕組み

定期実行は、これから来院予定で「確定」になっている予約を探し、患者へのリマインダーメールを作成します。以前は「翌日ぶんだけ」を見ていましたが、取りこぼしを防ぐために対象範囲が広がりました。

項目現在の動き
対象の期間いまから翌日の終わり(日本時間 23:59)まで。以前は「翌日ぶんだけ」だったため、夜中に入った翌日の予約が拾えないことがありましたが、今は必ず 1 回は対象になります
対象の予約状態が「確定」のものだけ。承認待ち・キャンセル済みには送りません
送らないものすでに開始時刻を過ぎた予約には送りません(いまから始まる予約だけが対象)。メールアドレスが登録されていない患者(電話予約のみ 等)にも送りません。どちらも正常な動作です
回数1 つの予約につき 1 回だけ。すでにリマインダーを作った予約は、以降の定期実行では飛ばされます

☞当日の予約にも届く場合があります

対象が「いまから翌日の終わりまで」に広がったため、当日これから始まる予約にもリマインダーが届く場合があります(例: 当日の朝に入れた夕方の予約)。メールの件名は「ご予約日のお知らせ」、本文は「ご予約の日時が近づいてまいりました」となっており、本文に実際の日時が入るため、当日でも翌日でも案内として正しく読めます。

5-4. 同じメールが 2 通届かない仕組み

定期実行は、まれに同じ時刻に二重で起動したり、送信の途中で止まってしまうことがあります。以前はこうした場合に同じメールが 2 通届く可能性がありましたが、現在は対策済みです。

  • 二重送信の防止 — 定期実行が重なって動いても、1 通のメールはどちらか一方だけが担当します。同じメールが 2 通届く事故は起きません。
  • 途中で止まったときの復帰 — 送信処理の途中で止まってしまったメールは、10 分後の定期実行で自動的に送信待ちに戻され、あらためて送られます。放置されたままにはなりません。
  • 送信に失敗したとき — 一時的な失敗は最大 3 回まで自動でやり直します。3 回で送れなかったものは「失敗」として記録され、それ以上は自動で送られません(STEP 4 の 4-5 参照)。

この仕組みは運用側で操作する必要はありません。「同じメールが 2 通届く」「送信中のまま止まる」といった事故が起きないようになっている、とご理解いただければ十分です。

5-5. 定期実行が登録されているか確認する

定期実行の内容はアプリのプログラムに含まれており、デプロイ時に自動で登録されます(手動設定は不要)。登録されているかは次で確認します。

  1. Vercel の Cron 画面を開くVercel のプロジェクト →「Settings」→「Cron Jobs」(またはプロジェクト上部の「Crons」)。
  2. 1 件登録されていることを確認パス /api/cron、スケジュール 0 * * * *(毎時 0 分)が表示されていれば OK です。
  3. 実行が成功しているか確認実行履歴で、状態が成功(200)になっていることを確認します。401 が並んでいる場合は、5-2 の CRON_SECRET が未登録か、登録後に再デプロイしていません。

5-6. 動いているかの確認方法

次のいずれかで、定期実行とメール送信が動いていることを確認できます。

方法A: 院内の設定画面で見る(いちばんかんたん・おすすめ)

院内の「クリニック設定 →『通知の送信状況』」(院長のみ表示)を開きます。直近 50 件のメールについて、状態が送信済みになっていれば動いています。待機中のままのものが 1 時間以上たまり続けている場合は、定期実行が動いていない可能性が高いので 5-2 と 5-5 を確認してください。

方法B: Vercel の実行ログを見る

Vercel のプロジェクト →「Logs」や「Cron Jobs」の実行履歴で、/api/cron が毎時実行され、成功(200)していることを確認します。

方法C: 手動で 1 回動かす 開発担当者

テスト送信をすぐ確認したいときは、定期実行を手動で 1 回呼び出せます。合言葉を付けないと必ず拒否されますので、CRON_SECRET の値が必要です。
