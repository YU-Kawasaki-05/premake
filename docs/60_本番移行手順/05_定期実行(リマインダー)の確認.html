STEP 5 定期実行の確認

前日リマインダーやメール送信を自動で動かす『定期実行』が本番で正しく動くことを確認します。メールが届くまでの仕組みも説明します。

目安 約20分確認中心

この STEP でやること

前日リマインダーやメール送信を自動で定期的に動かす仕組み(定期実行)が、本番で正しく動くことを確認します。特別な設定作業は少なく、『動いているかの確認』が中心です。

5-1. メールが届く仕組み(大事な前提)

premake では、確認・キャンセル・リマインダーのメールはすぐには送られません。いったん送信予約リスト(キュー)にためられ、『定期実行』がまとめて送信します。

タイミング起きること
予約作成・キャンセルなどメールが送信予約リスト(キュー)に積まれる
定期実行(/api/cron)が動くたまったメールをまとめて送信+前日リマインダーを作成・送信

ⓘつまり「メールの遅れ」は定期実行の間隔と同じ

このアプリの定期実行は1時間ごとに設定されています(設定ファイル vercel.json)。そのため、予約確認メールは作成から最大およそ1時間後に届きます。これは仕様です。リアルタイム送信ではない点を、運用でご理解ください。

⚠Vercel のプランに注意(重要)

1時間ごとの定期実行を動かすには、Vercel の有料プラン(Pro)が必要です。無料プラン(Hobby)では定期実行が1日1回までに制限され、予約確認メールが最大1日遅れるため、クリニック運用には向きません。本番運用の前に Vercel Pro への切り替えを推奨します。

5-2. 定期実行が登録されているか確認する

定期実行の内容はアプリのプログラムに含まれており、デプロイ時に自動で登録されます(手動設定は不要)。登録されているかは次で確認します。

  1. Vercel の Cron 画面を開くVercel のプロジェクト →「Settings」→「Cron Jobs」(またはプロジェクト上部の「Crons」)。
  2. 1件登録されていることを確認パス /api/cron、スケジュール 0 * * * *(毎時0分)が表示されていれば OK です。
  3. CRON_SECRET が入っているか再確認STEP 3 で CRON_SECRET を登録済みなら、Vercel が自動で合言葉を付けて実行します。未登録だと本番では実行が拒否されます。

5-3. 前日リマインダーの仕組み

定期実行は、「明日」来院予定で確定(confirmed)している予約を見つけ、患者へリマインダーメールを作成します。同じ予約に二重で送らないよう、送信済みの記録も残します。

メールアドレスが登録されていない患者(電話予約のみ 等)にはメールは送られません。これは正常な動作です。

5-4. 動いているかの確認方法

次のいずれかで、定期実行とメール送信が動いていることを確認できます。

方法A: Vercel の実行ログを見る(かんたん)

Vercel のプロジェクト →「Logs」や「Cron Jobs」の実行履歴で、/api/cron が毎時実行され、成功(200)していることを確認します。

方法B: データベースで送信状況を見る

Supabase の「Table Editor」で notifications テーブルを開き、status 列が sent(送信済み)になっているかを見ます。queued のまま残り続ける場合、定期実行が動いていない可能性があります。

方法C: 手動で1回動かす 開発担当者
