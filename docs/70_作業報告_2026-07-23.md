## 1. 目的と背景

2026-07-21 の品質監査で、仕様上「実装済み」とされていた機能に **36 項目の実装ギャップ**と **34 件の不具合**が確定した(docs/40)。加えて監査後の敵対的調査で **26 件の新規問題**(BC-NEW / NT-NEW / DB-N / AUTH)を発見。本作業はこれらのうち「MVP 必須(中核フロー直結・本番セキュリティ・法務)」を全て解消し、受け入れテスト仕様書を実装後の実態に整合させることを目的とした。

中核フロー = **「看護師が予約 → 病院側が確認 → スムーズに施術完了」**(決済なし・実在 1 院への導入前提)。

### 途中で発見・解決した重要問題
- **アプリ全体でトースト通知が不表示**(Toaster 未マウント。保存・変更の完了フィードバックが一切出ていなかった)→ 修正・実測確認
- **複合 FK 導入の副作用で PostgREST の関係取得が全面故障(PGRST201)**→ 全 10 箇所修正 + 開発規約化(AGENTS.md)
- **リスケの自己衝突問題**(同一予約の枠変更が DB 制約と衝突)→ EXCLUDE 制約の遅延評価化で解決
- 前セッションの「幻の完了報告」(ツール汚染)→ 全報告を git/fs 直接検査で裏取りするプロトコルを全工程に適用し再発ゼロ

## 3. 実施内容(時系列)

### 3-1. ★2 中核 6 件(コミット `a1f9843`〜`13d113a`)
| 項目 | 内容 |

| No.18 院内通知 | 公開予約が入ると院内(clinics.email)へ通知。承認漏れ=予約喪失を防止 |

| No.33 バッファ | メニューの清掃・準備時間が枠占有に反映されず背中合わせに予約が入る問題を、DB 制約レベルで解消 |
| No.1 リスケ | **予約変更(日時・担当・部屋)を新規実装**。台帳から数クリックで変更、患者へ変更通知 |

### 3-2. ★3 セキュリティ・品質(コミット `8b8685e`〜`6347ad4`)
- **DB 層防御**: スタッフ権限での改ざん迂回を RLS で遮断 / クロステナント参照を複合 FK 15 本で遮断 / seed の本番誤実行ガード
- **メール**: HTML エスケープ(フィッシング注入遮断)/ 送信失敗の自動リトライ / 差出人をクリニック名に / セルフキャンセル時の患者+院内通知
- **公開空き枠**: 退職者・非公開スタッフ・担当外メニュー・アーカイブ部屋の枠が患者に見える問題を解消 / スタッフ本名の露出防止
- **受付運用**: スタッフが他人の施術枠を管理可能に / 電話予約で非公開スタッフを担当指定可能に
- **検収品質**: favicon 差し替え / 患者向け画面の内部 ID 露出解消 / 「無断」→「不来院」/ ページタイトルからベンダー名除去 / OGP
